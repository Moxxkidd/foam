## 1. 目标、约束与取舍

目标：让授权使用者在 Kali 上，从配置、新建任务、观察/介入、结束、核验、恢复到交付结果，都能获得一致、可理解、可恢复的体验；保留自由 bash、任意工具通用路径、持久 PTY 和 operator 授权确认。

沿用的约束：Python ≥3.12、asyncio、保守依赖、标准库优先；不得为了演示放宽 scope；模型不自行扩权；模型/API 密钥只走环境变量；测试凭据明显合成；真实运行产物不入库；共享文档 append-only。

本轮规划假设：个人/小团队 Kali 使用者优先，TUI 为主入口，CLI 为自动化与复核入口；不先引入云服务、账号系统、商业集成或多 agent 编排。若目标转为浏览器主产品，应单独重排 R15–R24。

比较过的三种路线：

| 路线 | 收益 | 代价 | 建议 |
|---|---|---|---|
| 先修正确性与证据，再完善 TUI | 直接消除现有缺陷，界面有可信数据支撑 | 早期视觉变化不大 | **采用** |
| 先做 Web 工作台 | 容易集中展示结果和历史 | 容易把旧数据/生命周期缺陷带入新入口，增加部署面 | 作为 R24 条件项 |
| 先加多 agent/大量解析器 | 能扩展场景与并发 | 进一步放大资源、审计、授权和成本管理难度 | 暂不安排 |

版本号暂建议从 **0.1.2** 起：当前源码为 0.1.0，而交接记载曾到 0.1.1。R05 必须核实真实发布/tag 后再冻结编号；不得覆盖既有 release。下面的编号表示版本目标，不是已承诺发布日期。

## 3. v0.1.2：修复当前可复现缺陷

### R01 · 授权目标判定正确性 · 必选 / M

- **来源与依赖**：评估 E01/E02；无需新模块或真实模型。
- **交付**：URL origin 与路径前缀分开验证；nmap 请求地址集合完整覆盖检查；完善畸形输入和未知语法的处理。产品文案准确说明参数级与 PTY 的当前限制。
- **范围/候选文件**：`src/foam/guard/scope.py`、`tests/test_scope.py`；`agent/prompts.py`、README 的必要说明及快照测试。保留 CIDR/host/URL 规则现有“或”语义，不借机改成新的授权模型。
- **排除**：不声称完成网络级约束，不禁用自由 bash，也不以更多正则宣称消除脚本/PTY 绕过面。
- **验收**：[ ] E01/E02 原始复现变为拒绝；[ ] 同 origin 合法路径仍可通过；[ ] 无尾斜线/userinfo/相邻域名/端口/IPv6/非法 URL 覆盖；[ ] 离散网段、带空洞并集、多八位组范围覆盖；[ ] 大范围不能靠逐 IP 无界枚举。
- **风险与回退**：规范化不得扩大规则；新增拒绝应提供可行动原因。若规则语义需改变，写明迁移方式，不静默解释成更宽授权。

### R02 · scope 冻结、恢复和元数据一致性 · 必选 / L

- **来源与依赖**：E03/E07、metadata 非原子、TOCTOU、相对路径恢复；依赖 R01。
- **交付**：file/NL/resume 共用开跑前初始化；同一份输入字节绑定规则和哈希；显式覆盖持久化到当前 scope/目标；恢复重建正确动态段；标记 active/closed 的迁移符合实际运行。
- **范围/候选文件**：`state/files.py`、`agent/scope_compiler.py`、`cli.py`、`tui/app.py`、`agent/prompts.py`；对应 state/scope_compiler/cli/tui 测试。建议新增可恢复的 scope 修订记录和本地确认快照。
- **兼容决策**：file 流冻结副本是对 WP-14 Q8/D13 现有 as-given 外部文件契约的拟议修订，须在正式规格中明确批准；外部文件后续变化不自动成为新授权。旧 engagement 通过原始路径/hash 验证后才可迁移，不能猜测缺失范围。
- **排除**：不假装恢复已消失的远端 shell/PTY；不保证跨文件 rename 等价于事务。
- **验收**：[ ] A→B 收窄→再次 resume 始终 B；[ ] 新目标持续保留；[ ] 更换 cwd 可恢复新格式；[ ] file/NL 首轮都呈现真实范围；[ ] eager/普通调度一致；[ ] 在每个写入阶段注入故障，只能恢复已提交修订或明确拒绝；[ ] 同目录第二写者被拒；[ ] 旧链不重写。
- **风险与回退**：审计/metadata/快照需要可对账提交标识。升级前留元数据备份；迁移中断不改变旧授权，失败不自动退回更宽历史 scope。

### R03 · 统一运行时资源关闭 · 必选 / L

- **来源与依赖**：E04；依赖 R02 的运行状态约定。
- **交付**：CLI/TUI 共享资源所有权，bash 与 session 有幂等关闭路径；finished/error/kill/cancel 均停止新调度、清理本 run 进程、收割输出、落终态；异常期间也释放索引和后端连接。
- **范围/候选文件**：`tools/bash.py`、`tools/session.py`、`agent/loop.py`、`cli.py`、`tui/app.py`；新增 `src/foam/runtime.py` 仅在职责收口有必要时采用；tests/test_bash.py、test_session.py、test_loop.py、test_cli.py、test_tui.py。
- **排除**：不杀同机其他用户或不属于本 run 的进程；不新增无监督 daemon 模式。
- **验收**：[ ] 轮数耗尽/模型错误/外部取消/正常结束后本 run 无活动进程；[ ] 前台等待被取消也可收割；[ ] 孙代进程清理；[ ] 重复 close 无副作用；[ ] 清理有时间上界；[ ] 清理失败显示 failure/cleanup_pending，不显示全部完成。
- **风险与回退**：原提示“进程只会被 timeout/kill_job 终止”需随新生命周期契约更新；active 待命期间不自动结束资源，只有真实 run 退出才收口。避免先关审计后清理而丢失终态记录。

### R04 · 报告全量分页与真实统计 · 必选 / S

- **范围/候选文件**：`replay.py`、必要的 `state/index.py` 只读快照接口、`cli.py` 写文件路径；`tests/test_replay.py`、`test_cli.py`。
- **排除**：不扩大 LLM 单次 state_query 返回量，不做 HTML/PDF 排版。
- **验收**：[ ] 各相关表 0/1/500/501/1001 条；[ ] 首末条齐全、无重复；[ ] total 与内容相符；[ ] 并发写入时使用一致读快照或明确拒绝；[ ] 磁盘失败无“导出成功”假提示。

- **风险与回退**：目标凭证属于敏感成果，API 密钥仍只走环境变量。存储目录/数据库/转录采用仅本用户可读写权限；分享导出另走脱敏视图，不静默改变现有报告全值契约。

### R09 · verify、证据 manifest 与结项页 · 必选 / L

- **来源与依赖**：旧维护批 2/3、loot 快照语义；依赖 R04/R06–R08。
- **交付**：建议新增 `foam verify <dir>`；分别输出审计链、产物 hash、证据引用、终态/覆盖的核验状态；loot 记录登记时快照与最终核验时快照；任务终态生成确定性的证据摘要页，不依赖额外 LLM 才能保全结果。
- **范围/候选文件**：`guard/audit.py`、`tools/output.py`、`state/index.py`、`replay.py`、`cli.py`；可新增 `src/foam/evidence.py` 收口清单生成与验证。
- **排除**：不声称本地 hash 链具有外部不可抵赖性；不恢复从未记录的旧会话输入。

## 5. v0.2.0：明确执行边界与运行预算

### R10 · Kali 执行边界设计验证 · 必选 / L（先研究）

- **来源与依赖**：已知 PTY 无检查点、旧平台批 9；依赖 R01–R03，可提前于 R06 开展。
- **交付**：隔离 PoC 与威胁模型；比较 network namespace＋nftables、独立容器两种方案，确认权限、工具兼容、PTY、DNS、IPv4/IPv6、控制面通信和 cleanup 路径。研究结论先于生产接线。
- **范围/候选文件**：先在隔离 Linux 测试环境和 R 规格与验证记录落证据；必要的合成 fixture 进入 `tests/integration/`（拟新增），不改用户宿主机全局规则。
- **验收**：[ ] 两种候选的能力/成本表；[ ] bash/PTY/子进程都在预期隔离边界；[ ] 子进程无法改控制面规则；[ ] 故障回收不影响无关流量；[ ] 给出可支持规则子集和不支持情形。
- **关键限制**：nftables 只能直接表达网络层约束，不能单独验证加密 HTTP 路径、所有通配域动态解析、授权远端内部的再次跳转。远端 shell 的后续出站不受本机规则直接控制。域名绑定、DNS 变化、共享 IP、代理/隧道须明确威胁边界。
- **决策门**：若只能支持 CIDR/端口子集，明确展示该支持矩阵；无法等价执行的规则在受保护模式拒绝启动，不偷偷提升为更宽 IP 授权。R11 未通过前不宣称“任意 scope 均被网络层强制”。

### R11 · Kali 隔离执行路径落地 · 必选 / XL（须拆片）

- **来源与依赖**：R10 的经评审方案，R02/R03；不得跳过研究门。

## 10. 横向接口与迁移约定

正式规格应冻结下列边界；这里给出语义要求，不提前虚构最终函数签名。

| 边界 | 生产者 → 消费者 | 最低契约 |
|---|---|---|
| scope 修订 | R02 → 执行、恢复、UI、报告 | revision、来源、确认时间、规则、绑定 hash、提交状态；只有已提交修订可执行 |
| job/session 终态 | R03/R06/R07 → 索引、审计、UI | 稳定 ID、执行来源、终态原因、时间、产物引用；重放可幂等 |
| 发现与证据 | R08/R09 → R17/R24 | 来源、验证状态、引用、缺失状态分开；缺旧字段默认 unknown |
| 运行状态 | runtime/loop → R13/R16/R18 | 业务状态与工具活动分开，等待原因可见；任务目标达成不由退出码代替 |
| 预算 | R12 → 后端、UI、恢复 | 累计用量、估算标志、上限、停止原因；跨恢复保持一致口径 |

数据库迁移采用显式 schema version 和事务；新增表/字段优先向前兼容。旧二进制无法读取新格式时明确拒绝写入，不能静默重建空库。审计历史永不重写；新 reader 对旧 kind/缺失字段给兼容状态。运行目录迁移前提供备份与校验，不自动移动全部既有目录。

## 11. 验收矩阵与 UX 达标标准

| 层级 | 必测内容 | 执行时机 |
|---|---|---|
| 离线单元/契约 | scope 集合、URL、provider 帧、分页、去重、schema | 每个涉及模块的 R 或分片 |
| 组合回归 | 两次恢复、后台完成、退出清理、断点写入、并发打开 | v0.1.2 起持续保留 |
| TUI pilot | file/NL、eager/普通调度、焦点、快捷键、异常、恢复 | 每个 TUI/运行状态变更 |
| Linux 集成 | PTY、进程组、受保护出站、权限、故障回收 | 对应执行层 R 或分片；macOS 不能代替 |
| 真实模型 | 工具链、拒绝/中断、用量、选定 provider | 显式环境门控，不作为普通 PR 必跑 |
| 人工体验 | 真实中文输入法、终端布局、第一次使用、结果查找 | v0.3 候选发布 |

建议的 v0.3 用户验收任务与门槛（待执行的目标，不是当前成绩）：

1. **第一次启动**：至少 3 位未开发本项目、熟悉终端的试用者，在依赖已准备的条件下，仅依据产品提示完成配置确认、目标与 scope 确认；所有人不得误认授权状态。
2. **观察与介入**：给定运行/等待/暂停/确认/失败五类场景，每人能正确说出当前状态和可用操作；无需翻源码。不得出现“UI 已暂停、任务仍在派发”的错觉。
3. **结果定位**：在 100 条合成发现中按目标和状态筛选，找到指定发现及证据；建议目标为 60 秒内，先记录基线再评估改善。
4. **结束与恢复**：退出、重启、选择任务恢复，当前 scope/目标/已登记成果一致；旧 PTY 不假装复活，清理状态可查。
5. **报告交付**：1001 条数据不漏项，未验证/缺证据/未知字段可见；不把未完整评估的目标写成安全。
6. **输入与导航**：纯键盘、中文多行粘贴、80 列终端均可完成确认与结束；无意外提交、无安全快捷键失效。

竞品对照只评上述共同任务，固定模型、目标与机器并记录版本。报告任务完成率、误操作数、人工干预次数、耗时中位数与失败个案；样本少时保留原始分布，不以一次截图或一次成功宣称整体领先。

## 12. 发布门与近期执行建议

每个 R 或独立分片按 AGENTS.md §7 完成规格评审、逐条验收、必要回归和限定文件提交；规格与真实验证结果集中在 R 文档，状态写入版本清单，交接入口追加到 HANDOVER。版本发布另需安装包验证、完整用户旅程、公开边界/已知问题及迁移说明。本次制度迁移不触发产品开发或发布。

近期最小闭环：先只批准并执行 R01 的规格与修复，再依序处理 R02–R05。若 R02/R03 规格过大，拆成“契约与兼容”“实现与故障测试”可独立核销的小片，保持一次一个 R 或分片。安全/正确性片未过门时，不用 UI 优化替代其验收。

v0.1.3 后即可让使用者看到更可靠的成果登记和核验；v0.2 交付可控执行与预算；v0.3 才以完整任务体验作为主要发布承诺。是否达到 Strix/Cairn 的对应体验水平，以第 11 节的共同任务结果判断，不预先承诺总体追平。
