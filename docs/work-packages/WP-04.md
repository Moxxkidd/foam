# WP-04:agent 主环(loop + prompts + cli 初版)

状态:pending|依赖:WP-01(exec)、WP-02(护栏/审计)、WP-03(后端)

## 目标

把前三块拼成能跑的 agent:

- `loop.py`:AgentLoop 主环——
  - 消息状态机:user(objective)→ assistant(tool_call)→ tool 结果 → …
    直到 assistant 无 tool_call(finish)。
  - 工具调度:注册 WP-01 的 bash/output 工具;**每个 run_command 先过
    WP-02 scope 校验**,拒绝结果作为 tool 结果回给 LLM(纠正性说明);
    全程写 WP-02 审计链。
  - context 预算:token 估算(字符/4 粗估即可);超限先压缩旧 tool 结果
    (替换为"已压缩 + 路径 + 哈希"占位),再压缩旧对话;system 与
    ENGAGEMENT.md 永不压缩。
  - 插话队列:操作员消息在 turn 边界注入为 user 消息,不打断正在执行的
    工具;`kill` 立即 cancel 当前 turn 并 kill 全部后台 job。
  - pause:turn 边界停住,resume 继续。
- `prompts.py`:system prompt 构造——角色、**授权声明**(scope 文件摘要:
  目标列表与加载时间)、方法论骨架(recon→枚举→利用→后利用→报告,
  明示可自由裁剪)、工具使用纪律(大输出分页、发现入库占位、会话占位)、
  红线(不越 scope、不碰未授权目标)。工具地图留注入点(WP-08)。
- `cli.py` 初版:`theform run --scope <file> --objective "..." --backend
  <name> --workdir <engagement 目录>` headless 跑通(无 TUI)。

## 排除项

  状态入库工具(WP-06 的工具在 WP-04 之后注册,loop 的工具注册表要
  设计成可追加)。

## 验收标准

1. 合成 e2e:fake 后端(脚本化 tool_call 序列)驱动 loop 跑
   `nmap --version` 级别的无害命令,审计链完整、scope 校验被调用、
   最终 finish。
2. 越界命令 e2e:fake 后端请求 scope 外目标 → 拒绝 + 纠正说明回到
   消息流 + `exec_denied` 审计记录。
3. 压缩单测:构造超限对话,验证压缩顺序与 system/ENGAGEMENT.md 保留。
4. 插话/kill/pause 单测。
5. system prompt 快照测试:包含授权声明与红线;不含任何品牌名。
6. 开发日志记录真实 pytest 输出。
