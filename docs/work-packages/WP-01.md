# WP-01:exec 层 + 智能输出层

状态:pending|依赖:无(首批可开工)

## 目标

给 LLM 一个**自由 bash** 执行面,输出侧做智能处理,是全部后续 WP 的地基:

- `run_command(command, timeout_seconds, output_budget_bytes, background)`:
  经 `bash -c` 异步执行;前台等结果或立即返回 job id 后台运行。
- `read_output(job_id, offset, limit)`:分页读取任意 job 的完整输出。
- `list_jobs()` / `kill_job(job_id)`:后台 job 生命周期管理。
- 智能输出层:stdout/stderr **全量实时落盘**(engagement 目录,WP-06 之前
  先用调用方给的目录),记录 sha256;给 LLM 的视图做 head+tail 截断
  (保留首尾、标注省略字节数与总行数),防止大输出爆 context。

## 排除项

- PTY 交互会话(WP-05)。
- scope 校验(WP-02 包装,本 WP 只做执行与输出)。
- engagement 目录布局(WP-06);本 WP 输出落盘目录由调用方注入。

## 涉及文件(本 WP 拥有)

- `src/theform/tools/bash.py`
- `src/theform/tools/output.py`
- `tests/test_bash.py`、`tests/test_output.py`

## 设计要点

- asyncio 子进程;读流用异步迭代,边读边写盘边维护内存 ring buffer
  (最近 N KB,供快速 tail)。
- 输出预算:超过 budget 不杀进程,只截断 LLM 视图并提示"已落盘,可分页
  读取";进程只能被 timeout 或 kill_job 终止。
- 截断视图格式:`[前 H 字节] … 省略 X 字节/Y 行,完整输出 <路径>(sha256:…) … [后 T 字节]`。
- 返回结构:`{job_id, status, exit_code, duration_ms, output_view, output_path, sha256}`。
- 工具 schema(function calling 用)在本文件实现并导出,WP-04 直接注册。

## 验收标准

1. 单测全绿:截断字节账目精确(head+tail+省略数对得上)、分页读取与全量
   落盘内容一致、sha256 校验正确、timeout 终止、后台 job kill。
2. 长跑命令(如 `sleep 30`)后台化后前台不被阻塞。
3. 二进制/乱码输出不崩(错误替换策略),大输出(100MB 级)内存可控
   (ring buffer 有界)。
4. 开发日志记录真实 pytest 输出。
