# WP-07:parse 增强库

状态:pending|依赖:WP-06(索引层)

## 目标

把高频工具的输出变成 LLM 可消化、索引可收纳的结构——**增强而非门槛**:

- `parse.py`:解析器注册表,按命令行首 token 识别工具:
  - `nmap`(`-oX` XML,stdlib `xml.etree` 解析;也容忍 grepable 文本)
  - `sqlmap`(stdout 关键段 + loot CSV)
  - `gobuster` / `nikto` / `hydra` / `whatweb`(文本行解析)
- 每个解析器产出二元组:`summary`(≤500 字节的紧凑中文/英文摘要,给
  LLM)+ `facts`(原子事实 dict 列表,喂 WP-06 索引:host/port/service/
  cred/vuln)。
- **未知工具回退**:注册表未命中 → 不解析,只返回通用输出路径与截断
  视图(WP-01 已有行为)——LLM 用任何冷门工具都不被挡。
- 解析失败(输出格式变了/截断)永远静默回退通用路径,不抛给 LLM;
  记 debug 审计。

## 排除项

- 新工具的无限扩充(后续 WP 按需加解析器,本 WP 交付框架 + 上列 6 个)。
- 浏览器型工具。

## 涉及文件(本 WP 拥有)

- `src/foam/tools/parse.py`
- `tests/test_parse.py`、`tests/fixtures/`(合成样本)

## 验收标准

1. 每个解析器配合成 fixture(不得含真实目标数据),summary/facts 快照
   单测。
2. facts 进 WP-06 索引的集成单测:nmap fixture → hosts/ports 可查。
3. 未知工具与格式损坏两条回退路径单测。
4. 开发日志记录真实 pytest 输出。
