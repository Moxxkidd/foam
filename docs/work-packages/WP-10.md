# WP-10:CLI 闭环(run / tui / resume / replay / report)

状态:pending|依赖:WP-02、WP-04、WP-06

## 目标

把各块收成完整 CLI:

- `foam run --scope <file> --objective "..." --backend <name>
  [--workdir ...]`:headless 跑(WP-04 已初版,本 WP 收尾参数面)。
- `foam tui`:接 WP-09。
- `foam resume <engagement_dir>`:从 engagement 目录恢复——重建
  system prompt + ENGAGEMENT.md 摘要 + 最近 N 轮摘要,继续跑;
  明确限制:不做全量对话回放恢复(压缩后的形态继续)。
- `foam replay <engagement_dir>`:先用 WP-02 `verify` 校验哈希链,
  再按时间线只读重放审计事件(谁、何时、什么命令、什么结果元信息);
  链断即中止并报告断点 seq。
- `foam report <engagement_dir> [--out report.md]`:从索引库 +
  ENGAGEMENT.md + 审计链生成中文 markdown 报告(目标、范围、过程时间线、
  发现清单含证据路径、loot 清单、operator 插话记录)。
- engagement 生命周期:`run` 创建目录、`resume` 校验目录完整性、
  所有命令对缺文件给明确报错。

## 排除项

- 报告模板系统(v1);PDF/HTML 导出(v1)。

## 涉及文件(本 WP 拥有)

- `src/foam/cli.py`(在 WP-04 初版上扩展;两 WP 交接时在日志声明)
- `src/foam/replay.py`
- `tests/test_cli.py`、`tests/test_replay.py`

## 验收标准

1. replay 篡改 e2e:改动 audit.jsonl 任意字节 → replay 报告断链位置。
2. report 快照单测:合成 engagement 目录 → 报告含全部必备节。
3. resume 单测:恢复后 system prompt 含 ENGAGEMENT.md 摘要;目录缺
   audit.jsonl 时报错明确。
4. `--help` 全子命令可用且无品牌名外泄。
5. 开发日志记录真实 pytest 输出。
