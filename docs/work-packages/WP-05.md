# WP-05:持久 PTY 会话层(含 msfconsole)

状态:pending|依赖:WP-01

## 目标

重型交互工具的栖息地——本项目最硬的差异化:

- `session_open(command) -> session_id`:经 pty 启动持久进程
  (msfconsole/ssh/python -i/nc 监听等),异步读循环持续收集输出,
  全量落盘 + 哈希(复用 WP-01 输出层)。
- `session_send(session_id, text)`:写入(自动补行尾)。
- `session_read(session_id, wait_pattern?, timeout)`:返回增量输出;
  可选等待特定 pattern。
- `session_close(session_id)`;`session_list()`。
- **提示识别**:内置常见交互提示的正则库——sqlmap `[Y/n]` 系、
  `msf6 >` / `msf6 exploit(...) >`、ssh/sudo `password:`、
  `(yes/no)` fingerprint 确认等;命中时给 LLM 返回结构化
  `waiting_for_input` 事件(提示类型 + 原文),而不是一堆 ANSI 原文。
- ANSI/控制序列清洗:LLM 视图默认剥离,原文保留在落盘文件。
- msfconsole 适配:启动 banner 等待策略(`-q` 抑制)、提示符稳定判定、
  其 curses 风格输出的清洗特例;所有坑如实写进开发日志。

## 排除项

- meterpreter 会话的语义化管理(只保证通道可用;语义层后续 WP 再说)。
- tmux/screen 集成(不引入外部依赖)。

## 涉及文件(本 WP 拥有)

- `src/theform/tools/session.py`
- `tests/test_session.py`

## 验收标准

1. 单测:`python -i` 完成多轮 send/read;`cat` 回显;超时与关闭;
   提示识别正则对 fixture 文本的命中/不误报。
2. PTY 输出全量落盘且哈希可校验;LLM 视图 ANSI 已清洗。
3. 集成项(环境允许才跑,允许 skip):`ssh localhost` 到 password 提示
   被识别为结构化事件。
4. msfconsole:Kali 环境实测启动→banner→`msf6 >` 提示识别→
   `use`/`info`/`exit` 一轮;真实行为(启动耗时、输出怪癖)写进日志;
   非 Kali 环境该测试 skip。
5. 会话数量上限与孤儿进程回收策略有单测。
