# WP-02:scope 护栏 v0 + 哈希链审计

状态:pending|依赖:无(首批可开工)

## 目标

两条产品底线的 v0:

**scope 护栏**(`guard/scope.py`):

- 解析 scope 文件(每行一个:CIDR / 主机名 / `*.`通配域 / URL 前缀;`#`
  注释;见 `scopes/lab.scope`)。
- `extract_targets(command)`:从命令行 token 中识别 IP/主机名/URL
  (启发式,覆盖常见位置参数与 `-h/-t/--target/--url/-u` 等常见 flag 值)。
- `check_command(command, scope)`:所有识别出的目标都在 scope 内才放行;
  越界→拒绝 + 审计记录 + 给 LLM 的纠正性说明。
- **明示限制**(写进 docstring 与日志):shell 变量间接引用、管道拼接等
  混淆可绕过参数级校验;网络出口级强制(nftables)在 v1 立项补齐。

**审计链**(`guard/audit.py`):

- append-only JSONL;每条记录 `{seq, ts, kind, payload, prev_hash, hash}`,
  `hash = sha256(prev_hash + canonical(payload))`,首条 prev_hash 为零串。
  **更正(2026-08-20,实现以此为准)**:哈希输入已扩为覆盖
  seq/ts/kind/payload 全部字段——仅覆盖 payload 时,篡改 ts/kind/seq
  不断链,达不到验收 4「任意字节」的意图;详见 `docs/dev-logs/WP-02.md`。
  防篡改粒度为**语义字段级**(canonical 化后语义等价的字节变动,如
  JSON 字段间空白,不在检测范围)。
- kind 至少:`scope_loaded / exec_request / exec_denied / exec_result_meta /
  operator_interject / kill_switch / llm_exchange_meta`(LLM 内容只记哈希
  与 token 数,不记全文——输出原文在 engagement 目录)。
- `verify(path) -> bool`:全链重算校验,篡改任何字节都会断链。

## 验收标准

1. scope 解析表驱动单测:CIDR 包含/不包含、通配域、URL 前缀、注释空行。
2. 命令目标提取:常见 flag 与裸位置参数;误判率案例记录进日志。
3. 越界命令被拒且审计链出现 `exec_denied`;合法命令不受影响。
4. 哈希链:随机篡改任一记录任意字节,`verify` 必失败;追加 1 万条性能
   可接受(<1s)。
5. 开发日志记录真实 pytest 输出与已知的绕过面清单。
