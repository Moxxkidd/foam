# WP-09:TUI(迎宾屏 → 主界面)

状态:pending|依赖:WP-04

## 目标

观感对齐 strix / Claude Code 的终端体验:

- **迎宾屏**:启动进入全屏欢迎界面(大号字标、版本、当前后端/模型、
  scope 文件状态),输入操作员呼号后回车进入主界面——"输入名字才进入
  属于自己的 TUI"。
- **主界面**三件套:
  - 叙述流(主区):agent 的自然语言叙述、工具动作卡片(命令、运行状态
     spinner、截断输出、解析摘要、发现提示),渗透阶段推进以自然语言
    分隔条呈现("—— 进入枚举阶段 ——"由 loop 事件驱动)。
  - 侧栏:jobs/sessions 列表面板 + 状态摘要(host/端口/凭据/漏洞计数,
    来自 WP-06 索引)+ 当前阶段。
  - 底部输入框:随时输入自然语言插话(进 WP-04 插话队列);`Ctrl-X`
    触发 kill(二次确认,防误触)。
- 语义色与排版克制:阶段/成功/失败/警告各有稳定色;不只靠颜色传达
  状态(同时有文字标记);无花屏、无日志滚动条式信息倾泻。
- `foam tui`(或 `run --tui`)启动;TUI 与 headless 共用同一 loop
  事件流(loop 发事件,TUI 订阅渲染,headless 打印)。

## 排除项

- Web UI;鼠标交互深耕;主题系统(一套精心设计即可)。

## 涉及文件(本 WP 拥有)

- `src/foam/tui/`(app.py、widgets.py、styles.tcss 等自行组织)
- `tests/test_tui.py`

## 验收标准

1. textual pilot 单测:迎宾屏输入呼号 → 主界面挂载;叙述流追加;
   jobs 面板更新;kill 二次确认状态机。
2. loop 事件 → TUI 渲染的契约单测(fake loop 事件序列)。
3. 人工观感验收:与 strix/Claude Code 截图级对比的自查记录进开发日志
   (文字描述即可,不入图)。
4. 开发日志记录真实 pytest 输出。

## 设计定案(2026-08-22 grilling;与上文冲突以此节为准)

- **Q1 迎宾屏=纯呼号门**:scope/backend 走 CLI 参数(`foam tui --scope
  X --backend Y`,强制显式授权声明);objective=主界面输入框首条消息,
  loop 在首条消息前不启动;resume/replay 归 WP-10 子命令,迎宾屏不做
  入口菜单。
- **Q2 工具卡=紧凑流+异常自展开**:运行中 spinner+命令一行;完成折叠
  为「命令+状态+一行摘要」;Enter 展开 WP-01 head+tail 截断视图;护栏
  拒绝/非零退出/纠正事件自动展开。
- **Q3 阶段分隔条=ENGAGEMENT.md 驱动**:模型每轮维护「当前阶段」字段
  (WP-06 update_progress),loop 状态事件携带,TUI 检测变化渲染分隔条。
  不维护工具→阶段推断表,不要求 [PHASE] 标记。
- **Q4 控制面=Claude Code 式双通道**:输入框一切文本=插话;`/` 前缀
  harness 命令带补全(v0:/help /pause /resume /kill /jobs /sessions
  /status);硬键 Ctrl-X kill(二次确认)+ Ctrl-P pause/resume。
  **不做 `!` 前缀直跑 shell**(绕护栏破审计;v1 候选且须过护栏,入
  WP-13 v1 清单)。
- **Q5 PTY 会话=只读+插话转达**:不做接管模式、不预留接口;会话干预
  一律经 LLM session_send,天然全审计。
- **Q6 K3 推理流=折叠思考块**:backends 新增 ReasoningDelta 事件
  (base.py 事件类型 + openai_compat.py 解析 reasoning_content,Claude
  端可不发),loop 透传并加 LoopObserver 钩子——**涉及 WP-03/WP-04 已
  关闭文件的最小改动,按契约在开发日志声明**;TUI 灰色可折叠块默认
  折叠(🧠 思考 Ns [展开]);思考内容审计只记哈希。
- **D1 呼号去向**:engagement.json `operator` 字段 + operator_interject
  审计载荷带呼号;另存 `~/.foam/` 本地配置,下次启动预填。
- **D2 context 可视化**:侧栏 token 预算条(字符/4 估算);压缩事件在
  叙述流留痕(on_compressed 钩子)。
- **D3 侧栏**:右侧 ~30 列;终端 <110 列自动隐藏,F2 唤出;自上而下:
  当前阶段 → 状态摘要(hosts/ports/creds/vulns 计数)→ jobs/sessions
  面板(waiting_for_input 高亮)。
- **D4 色彩**:深色一套;阶段 cyan/成功 green/失败 red/警告 yellow/
  思考 gray/插话 blue;全部配文字标记双通道。
