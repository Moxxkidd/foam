# WP-11:e2e 场景一——容器靶场 Web 全链

状态:pending|依赖:WP-04~WP-08

## 目标

第一个真实验收:对**本地容器靶场**(Juice Shop 或 DVWA,docker 起,
写入 scope)全程自主:

预期链(不给 agent 剧本,只给 objective):nmap 识别服务 → Web 枚举
(whatweb/gobuster 类)→ 发现注入点 → sqlmap(经 PTY 会话处理交互)→
loot 落库 → 报告生成。

- 环境准备文档:`docs/e2e/scenario1-setup.md`(容器起法、scope 文件、
  端口)。
- 执行:`kalicode tui/run` 真实后端(Kimi K3 优先)跑 objective;
  操作员只观察与必要的插话(插话次数如实记录)。
- 产出:`kalicode replay` 校验通过 + `kalicode report` 报告入库
  (`docs/e2e/scenario1-report.md` 摘要 + engagement 目录位置)。

## 排除项

- 修 agent 暴露的能力缺陷(发现即记录,列入后续 WP;不为通过验收改
  oracle/护栏)。
- 靶场加固/绕过教学。

## 涉及文件(本 WP 拥有)

- `tests/e2e/`(环境脚本)、`docs/e2e/`(场景文档与结果)

## 验收标准

1. 全程零人工触碰工具机械细节(只允许自然语言插话)。
2. loot(数据库 dump 片段或等效证据)进索引库且路径可核。
3. 审计链 `verify` 通过;报告含完整时间线。
4. 如实记录:provider 审核事件、agent 走偏与纠正、插话次数、耗时、
   token 消耗。
5. 未达标项不得隐瞒——写进日志与 HANDOVER 已知问题。
