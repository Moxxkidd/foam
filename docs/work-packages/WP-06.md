# WP-06:状态层(engagement 目录 + SQLite 自动索引)

状态:pending|依赖:WP-01

## 目标

渗透状态的家——文件为主、索引加速:

- `state/files.py`:engagement 目录布局(创建/校验):
  ```
  engagements/<id>/
    engagement.json      # 元数据:objective、scope 文件哈希、起止时间
    ENGAGEMENT.md        # 每轮必载的进展摘要(loop 维护)
    audit.jsonl          # WP-02 审计链
    outputs/             # 工具原始输出(WP-01 落盘处)
    loot/                # 战利品文件(dump、截图、key)
    notes/               # 自由笔记
    index.sqlite         # 本 WP 的索引库
  ```
- `state/index.py`:SQLite 表——`hosts(ip, hostname)`、`ports(host_id,
  port, proto, service, product, version)`、`creds(host_id, username,
  secret, source, sensitive=1)`、`vulns(host_id, kind, title, evidence_path,
  confidence)`、`loot(path, kind, note)`、`notes(ts, text)`。
  通用 upsert/查询接口;解析器(WP-07)与 state 工具都走这层。
- `tools/state.py`:LLM 工具——`state_query(kind, filters)`(如
  "哪些 host 开了 445")、`state_add_note(text)`、`state_add_loot(path,
  kind, note)`。creds 在**给 LLM 的查询结果里默认脱敏**(掩码中段),
  完整值只在落盘文件;导出报告(WP-10)再含完整值。
- `ENGAGEMENT.md` 维护接口:loop 每轮结束更新进展摘要(最近阶段、
  关键发现计数、当前目标)。

## 排除项

- 跨 engagement 的经验库(远期)。

3. 脱敏单测:state_query 返回的 creds 被掩码,落盘文件完整。
4. state 工具 schema 与 WP-01 工具同构,可被 WP-04 直接注册。
5. 开发日志记录真实 pytest 输出。
