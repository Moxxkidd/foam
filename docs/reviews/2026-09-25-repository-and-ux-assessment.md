日期：2026-09-25。对象：本地 HEAD `3a9d07c7da9130e99681a48b5c8975b84b511492`。

状态：评估结论与版本建议，未实施修复。本报告与[后续版本迭代清单](../roadmap/2026-09-25-release-roadmap.md)配套；AGENTS.md 与 HANDOVER.md 仍是仓库契约和当前开发状态的事实源。本报告不把候选事项自动变为已批准 WP。

## 1. 结论

Foam 已形成有实际价值的早期产品：通用 bash 与解析增强分离，持久 PTY、流式输出、状态索引、审计、NL scope 确认和连续对话已经贯通。对于熟悉 Kali、愿意查看终端输出的使用者，核心操作路径具备可用性。

当前阻碍进一步交付的主要问题是：授权判定存在误放行、恢复时当前状态不能可靠延续、后台任务生命周期未闭合、报告与结构化结果可能漏项。界面已经有工具卡、折叠、异常提示和侧栏，但用户仍需自行拼接“发生了什么、发现了什么、是否已经停止、下次如何继续”。

建议采取“正确性维护 → 证据完整 → 可控执行 → 完整任务体验 → 兼容与扩展”的路线。暂不以增加工具数量、多 agent 数量或开屏动效作为主目标。网络级执行边界应提前研究，不能等所有界面功能完成后才处理。

## 4. 已确认问题及处理建议

这里的 P1 表示需优先修复的边界/生命周期问题，P2 表示结果完整性或体验问题，P3 表示文档维护。它是本报告的紧急程度；不覆盖 HANDOVER 旧清单中按主题分配的 P0–P3 标签。

### E01 · P1 · URL scope 会匹配不同的实际主机 · A

- 位置：`src/foam/guard/scope.py:229`。
- 输入：scope 为 `https://example.com`；检查目标 `https://example.com.testonly.invalid` 或 `https://example.com@other.testonly.invalid/`。
- 实际结果：两者均 `allowed=True`；判定测试不发网络请求。
- 根因：对完整字符串先做 `startswith`，命中后直接返回，未先确认实际 scheme/host/port。
- 建议：分别解析和验证规则与目标，先比较规范化 origin，再执行约定的路径前缀语义；畸形 URL 拒绝，不能要求用户自行补斜线来规避。
- 验收重点：无尾斜线、userinfo、相邻域名、端口边界、IPv6 authority、大小写、路径编码与非法输入。绑定 R01。

### E02 · P1 · nmap 范围只验证端点 · A

- 位置：`src/foam/guard/scope.py:243`。
- 输入：只授权 `192.0.2.1/32`、`192.0.2.254/32`。
- 实际结果：`nmap 192.0.2.1-254` 放行，但单独检查 `192.0.2.2` 被拒绝。
- 根因：将多个授权网段的并集当成一个没有空洞的区间；只验证两端不足以证明全部地址获授权。
- 建议：检查请求地址集合是否被授权集合完全覆盖；nmap 多八位组范围应按实际集合语义处理，不能简单假定都是一条连续数值区间。
- 验收重点：离散网段、有空洞的并集、相邻覆盖、多八位组范围、大范围输入的有界计算。绑定 R01。

### E03 · P1 · resume 的重新授权与目标覆盖未持久化 · A

- 位置：`src/foam/cli.py:999`，以及 `:875` 的 metadata 优先恢复。
- 复现：A 为 `/24` → `resume --scope B --objective 新目标`，B 为单个 `/32` → 再次不带覆盖参数 resume。
- 实际结果：三次均正常退出；最终恢复 A 和旧目标，metadata 仍指向 A。
- 根因：即时执行与动态段使用了新值，engagement.json 没有同步，下一次恢复优先读旧记录。
- 建议：统一 scope/目标的状态迁移，保留确认事实与历史谱系；原子写单个文件还不等于多文件事务，需要提交标识和崩溃对账策略。
- 验收重点：连续恢复、收窄再恢复、改 cwd、文件改动、落盘各阶段故障、并发打开同一任务。绑定 R02。

### E04 · P1 · 错误结束后后台进程未被回收 · A

- 位置：`src/foam/cli.py:639`、`src/foam/agent/loop.py:970`、`src/foam/tui/app.py:1442`。
- 复现：fake 模型启动 `sleep 30` 后台任务，`max_rounds=1`。
- 实际结果：`_drive` 返回 1、loop 为 error，job 仍为 running。脚本随后显式 kill 并收割。
- 根因：bash job 清理集中在 kill 分支，普通/error 的资源收口未覆盖 bash；不同入口各自关闭资源。
- 建议：给 run 统一资源所有权；默认禁止无监督任务脱离 run 存活。停止调度、关闭进程组、收割、完成输出、记录终态，再封闭审计。
- 验收重点：finished/error/cancel/kill、模型失败、轮数耗尽、前台取消、进程孙代、重复关闭。正常 finished 分支缺口来自代码检查，本轮具体复现的是 error 路径。绑定 R03。

### E05 · P2 · 报告超过 500 条静默漏项 · A

- 位置：`src/foam/replay.py:457` 与 `src/foam/state/index.py:374`。
- 复现：索引写入 501 条合成笔记。
- 实际结果：报告导出 500 条，统计也写 notes 500，没有截断提示。
- 根因：报告请求 10000 行，索引层限制最多 500；报告忽略 `total/truncated`。其他表复用相同调用路径。
- 建议：报告分页读取全部数据，在一致的读取快照内生成；总数来自真实查询结果，流式输出可作为大结果集优化。
- 验收重点：0/1/500/501/1001 条、最后一条、分页去重、报告中途失败、生成时新增记录。绑定 R04。

### E06 · P2 · 后台完成没有接入解析和终态审计 · A（fixture）

- 位置：`src/foam/agent/loop.py:794`、`:827`。
- 复现：同一 nmap fixture 分别走 completed 即时返回和 running→completed 轮询路径。
- 实际结果：前者 hosts=2、ports=4；后者 hosts=0、ports=0，exec_result_meta 只有 running。
- 根因：消费只挂在 run_command 的即时返回；后台实际完成没有独立事件驱动，list_jobs/read_output 不补做。
- 建议：由 job 完成事件驱动解析、索引和审计，按稳定 job ID 幂等消费，不能要求模型一定再查询才完成入库。
- 验收重点：无轮询也完成入库、重复通知不重复登记、重启后补偿、解析失败不吞原始证据、退出前消费完成。绑定 R06。

### E07 · P2 · TUI file scope 首轮信息面不一致 · A（9 月 23 日）

- 位置：`src/foam/tui/app.py:975`、`:1368`；HANDOVER 已登记。
- pilot 结果：实际 scope 包含 `127.0.0.0/8`、localhost；首轮 system 上下文仍含“scope 尚未冻结”，没有 `/8` 规则。
- 影响：护栏执行面已加载，模型获得的信息却与执行状态冲突；不能把这个问题描述成护栏未启用。
- 建议：file/NL/resume 共享开跑前状态准备；同一份输入字节同时生成内存规则、哈希、持久快照和模型动态段，关闭现有 TOCTOU 窗口。
- 验收重点：普通/eager 调度、首轮快答、文件在迎宾等待期变化、空 scope。绑定 R02。

### E08 · P3 · 发布版本与当前状态文档不一致 · B

- `pyproject.toml`、`src/foam/__init__.py` 都是 0.1.0；HANDOVER 记载 0.1.1；README 当前状态仍为 WP-13/383 tests，HANDOVER 最近基线为 526+2。
- 当前实测来源是 9 月 23 日的 533+2。没有追查版本漂移是在哪次提交产生，也不推断远端已发布 tag 的状态。

## 5. 已知限制与未量化风险

| 项目 | 证据/边界 | 推荐处置 |
|---|---|---|
| PTY 无 scope 检查点 | loop 只包裹 run_command；会话可绕开参数检查，已登记 | R10–R11；同时 R01 校正能力描述 |
| 会话操作与提示事件审计缺失 | known-issues ④⑤ | R07 |
| 手工/非注册工具成果缺登记 | state 工具仅 query/note/loot | R08 |
| 版本号误判为目标、总结纠正误报 | known-issues ②⑦ 的历史实弹记录，本日未重演 | R01 收案例，R14 做语义治理 |
| 模型主动截断扫描输出 | known-issues ③ | R06 提供完整产出通路，R14 改提示 |
| metadata 非原子、scope 加载/哈希不同时间 | known-issues D 附记 | R02，不能以 rename 一项宣称整个事务原子 |
| loot 大小是登记时快照 | known-issues ⑥ | R09 区分登记快照与结项核验 |
| 文件/索引敏感数据权限 | 代码有明文目标凭证存储契约；未做权限攻击复现 | R08–R09 确定本地存储与导出策略 |
| 上下文压缩后仍可超预算 | `_maybe_compress` 记录 still_over_budget，但不强制收口 | R12 |
| 状态笔记口径不一致 | 模板宣称 loop 每轮写进展，实际主要依赖模型写笔记 | R02/R16；不得凭工具名称伪造业务阶段 |
| 外部 scope 文件使用 as-given 路径 | 改 cwd 或删除文件会影响恢复 | R02 快照＋旧格式兼容 |
| 相同 workdir 在 run/TUI 含义不同 | run 为准确目录，TUI 为父目录 | R15 明确参数迁移与兼容提示 |
| 多后端/真实交互覆盖有限 | Claude 等缺 live 证据、sqlmap 向导实弹未覆盖 | R21/R22 |
| 长任务内存、磁盘与 UI 增长 | 未作长期压测，不断言已有性能退化 | R20；输出落盘也要处理磁盘耗尽 |

审计链校验只证明给定数据的链内一致性。缺少外部可信锚点时，不能独立检测合法截尾或有写权限者重建整条链；漏记的事件也不会因 verify 通过而自动补齐。后续核验 UI 必须明确区分“链通过”“证据文件匹配”“事件覆盖已知”“外部锚定状态”。

## 6. 用户体验与竞品参照

比较范围为当前开源、本地使用路径，不把商业云服务计入开源仓库能力，也不把文档宣称等同于实测可靠性。以下来源于 2026-09-25 刷新的官方资料。

Strix 本地 viewer 提供概览、发现详情/复现步骤、agent 图及历史入口；独立 viewer 与运行中界面的控制能力有区别，部分历史/报告功能还有邮箱验证条件。值得借鉴的是集中消费结果的流程，不是简单复制页面数量。[官方 viewer 文档](https://docs.strix.ai/usage/viewer)

Strix CLI 已定义费用预算及达到预算后的停止/暂停行为，并说明在途调用可能超支、费用属于估算。Foam 可以借鉴明确的边界与状态反馈，不能承诺精确扣费上限。[官方 CLI 文档](https://docs.strix.ai/usage/cli)

Cairn 以 Fact、Intent、Hint 组织确认事实、探索方向与人工输入，并采用 server/dispatcher 运行结构。可借鉴的是探索过程的可理解性；Foam 无需为获得这种体验先改成多 agent 架构。[Cairn 官方仓库](https://github.com/oritera/Cairn)

| 用户旅程 | Foam 已有基础 | 当前缺口 | 建议验收任务 |
|---|---|---|---|
| 初次启动 | profile、.env、scope 仪式 | 环境故障定位弱，配置生效来源不够集中 | 缺 key/错误路径/不可用后端能在 UI 找到具体处置 |
| 开始任务 | 首条目标消息、授权卡 | 已授权范围与目标状态须一致 | 从新建到第一条命令无隐含重授权、无错位提示 |
| 观察执行 | 工具卡、异常展开、侧栏 | 难看清已确认发现、待验证线索和当前阻塞 | 使用者能回答“正在等谁、是否需介入” |
| 介入与停止 | 插话、暂停、kill、scope 热换 | 正常结束、立即终止、停止调度易混淆 | 暂停边界可见，结束后无幽灵任务 |
| 消费结果 | Markdown 报告与索引 | 发现/证据/复现分散，报告漏项 | 从发现列表直接定位证据，并识别未核验项 |
| 退出与恢复 | CLI resume | TUI 任务列表/恢复缺失，历史状态一致性有 bug | 重启后恢复同一任务、相同 scope、可见资源丢失情况 |

结论：Foam 的终端交互基础值得保留，但完整任务体验尚不能据此宣称达到 Strix；与 Cairn 则应按过程可理解性比较。现有“截图级可比”的历史验收只能证明局部观感，不是产品成熟度的独立证据。

## 7. 质量与发布建议

- 对 E01–E07 增加具体回归用例；优先组合行为，不以增加断言数量为目标。
- 每个版本保留真实命令输出、环境与 SHA；mock、Linux 集成、live 模型测试分别标注。
- 建立最小权限 CI；默认用合成数据和本机隔离 fixture，不因普通 PR 自动接触真实目标或真实密钥。
- 每次改变 SQLite、审计事件或 scope 持久化，提供旧数据读取、升级故障恢复和降级约束。旧字段缺失必须显示 unknown/legacy，不伪造零值或已验证。
- 性能目标先测基线再定阈值；费用估算缺价格/usage 时显示不可用，不能显示零成本。
- 对选定真实靶场保存可复现环境、成功判据、token/耗时/人工介入和证据覆盖；不将新功能成立与模型某次碰巧成功混为一谈。
