## 1. 问题、目标与边界

- **来源与依赖**：R10 的经评审方案，R02/R03；不得跳过研究门。
- **交付**：将 bash、PTY 及其后代置于受保护执行环境，控制面/LLM 通道独立；工具进程不继承模型 API 密钥，不可访问管理套接字/修改规则；规则安装失败拒绝启动受保护 run。限制目标侧进程可修改的控制元数据，审计以控制面事件为准。

实现面：`guard/network_helper.py` 收拢严格结构化 helper 协议、五类
capability/securebits/NNP 回读、per-run netns/veth/nft NAT、PID namespace

本轮开始复跑曾得到 **152 passed, 2 skipped, 6 failed**。根因与修复：
NAT 缺本 run 入口接口匹配；cleanup 未跟踪实际创建的资源、resolver 清理
异常被吞；代际终止失败过早丢弃恢复身份；Python 3.12 的
`asyncio.subprocess.Process.wait()` 等待进程退出及全部管道断开，组外后代

`returncode`，正常输出仍有界排空，超时明确报告「输出可能未收尽」。
PTY 回归另修正场景准备竞态：子进程 ready 后 leader 才退出，并显式延后
macOS 提前到达的 EOF；保留组外后代存活、原文精确相等和未收尽告警断言，
未通过 skip、删断言或放宽 scope 取得绿色。

### R11-B 完成证据（2026-11-04）

基线为 `b7e6690`。实现面：run/resume/TUI 均要求显式
`--execution-mode protected|legacy`，不从 env/profile 推断；protected
把授权字节/canonical digest 绑定到 NetworkBoundary，并为 Bash/PTY 注入
同一 ToolExecutor。legacy 明示参数级护栏、继承环境、无网络强制和旧连接
不撤销；protected 启动失败明确报错，不回退。

热收窄由 `AgentLoop.replace_scope` 统一协调：暂停新派发并等待在途
spawn+注册 → 终止旧 PID namespace init → 收割 Bash/PTY 并排空旧事件 →
安装新规则、精确清 conntrack、创建 fresh PID namespace/init → 成功后才换
scope/epoch、恢复派发。Bash/PTY 新增区别于终态 `aclose` 的代际 `retire`；
成功后旧 id 作废。PTY 的 spawn 到注册也纳入代际锁，在途已获准 spawn
不被 pause 误杀。TUI 的 scope 引用与成功提示延迟到换代完成之后；失败保持
停止并将 run 置为 error。

有效红基线包括：真实 Linux 旧连接用例在实现前以
`TypeError: AgentLoop.replace_scope() got an unexpected keyword argument 'digest'`
失败且 cleanup=clean；PTY 竞态用例观察到 transition 在注册前进入；TUI
应用失败用例确认 run 虽终止却仍过早替换配置引用。均已转绿，未通过放宽
scope、删除断言或默认 skip 取得通过。组合回归初跑另有一项固定卡片序列
因新增执行模式 NoticeBlock 失败（424 passed、2 skipped、1 failed），更新

  当前 HEAD 祖先。R10 的 28 项 opt-in 与 R02/R03 对应前置回归在本次
  开工时重新执行，真实输出记录到 §6，不沿用历史绿标签。
- 现行 Bash/PTY 都直接 `bash -c` 并继承完整环境，PTY 不经命令级 scope
  检查；`AgentLoop.replace_scope` 只换引用；R03 只收进程组，detached
  后代、fresh `/proc` 和 Foam 崩溃后的 namespace 回收均无生产保证。
  R10 的 `TESTED_WRAP`、pidfd、netns/nft 仅是实验代码，不能误当已接线。
- **接口漂移一**：现有 `Scope` 只有 CIDR/hosts/wildcards/URL，没有协议
  或端口授权字段。**接口漂移二**：R02 `meta["revision"]` 可指向
  `run_started`/`scope_loaded`，不能直接当作 scope 确认事件。边界输入
  因此是已确认的 `Scope`、授权字节/canonical 哈希和显式 DNS 配置；
  不伪造 seq/hash 或做 metadata 迁移。CIDR 内的普通 TCP/UDP 任意端口
  （含 TCP/53）属于现有授权语义，须重新实证，不能沿用 R10 的 TCP/53
  拒绝结论。raw/AF_PACKET 不支持。
- **执行模式**：run/resume/TUI 均要求显式 `protected` 或 `legacy`，未
  选择即拒绝，不从 env/profile 猜测。legacy 明示仅参数级 bash 检查、
  无网络强制、PTY/已有连接不等价且继承环境；protected 任何失败不得
  自动回落。macOS、非 root、能力不足和不可信 helper 代码路径均明确
  unsupported。
- **权限定案**：首个受保护配置限定为「root Foam 控制面＋限权 helper
  ＋非 root 工具」，只在操作员已以 root 启动 Foam 的 Linux 环境使用，
  不自动 sudo，不泛称整个系统最小权限。helper 以隔离解释器、受信绝对
  源码和最小环境启动，收五类 capability/ambient/bounding、securebits
  与 NNP 后才监听；仅接受严格结构化 create/apply/close/status/recover，
  不接受任意 shell/nft 文本。工具固定 UID/GID 65534、capability 全零、
  NNP=1、白名单 env 与独立 scratch cwd。
- **网络与旁观者**：per-run netns/veth/inet nft NAT44/NAT66 只匹配本 run
  接口和地址；默认接受无关转发，不复制 R10 的全局 `forward policy drop`。
  input 仅放必要 IPv6 ND 后拒绝工具到控制面；conntrack 只按本 run 源
  地址删除，不做全局 flush。所有特权实验仅在专用 Docker harness 内，
  不改 macOS 宿主防火墙、全局规则或 Docker daemon 配置。
- **热收窄**：先阻断新派发及 spawn 注册竞态，再 kill 旧 PID namespace
  init、收割包装/输出、排空旧事件，安装新规则并精确清 conntrack，最后
  创建全新 PID namespace/init 和 fresh proc。旧 job/session 不再可用，
  成功后才换 scope/epoch、显示成功并恢复新派发；任一步失败保持停止并
  终止 run。PID namespace init 死亡后不能复用该 namespace 创建新 init，
  不得以原文本替换规则冒充已有连接撤销。
- **崩溃分级**：Foam SIGKILL/第二次 Ctrl-C 由 helper 的控制连接 EOF
  自动清理；helper 自身死亡依靠 root-owned manifest、pidfd/启动身份和
  重启对账补偿，不宣称即时清理。资源归属不明即拒绝，管理调用有超时，
  成功但客户端断连也须可对账。
- 支持集仅 CIDR；hosts/wildcards/URL 与混合 scope 整体拒绝，空 CIDR
  表示拒绝全部网络目标。DNS 仅允许显式且落在授权 CIDR 内的解析器；
  代理环境清除，界内代理/隧道与远端第二跳仍不作端到端授权承诺。
- 评审门结论：R10/R02/R03 依赖真实存在，授权内的常规实现可推进。上述
  root 控制面限制、换代杀旧工具和 helper 死后补偿是收窄的兼容决策，
  不需要扩大用户授权；无未决重大取舍。R11-A 先实现边界和工具适配，
  R11-B 再接全入口/热收窄，R11-C 完成故障矩阵，不提前关闭父条目。
