**定案决策**（1/2 为规格 §7 评审门要求的冻结项）：

1. **去重键冻结**：vulns=(host_id,kind,title)、creds=(host_id,username,secret) 既有自然键不变；不做任何模糊相似合并（规格红线）。重复登记返回同一逻辑实体（同一 record_id）；证据 refs 并集追加不丢（read-modify-write 在单事务内，复用 `_transaction`，add 路径事务感知以兼容 consume_job_exit 的既有外层事务）；verification_status 不可经登记路径降级（已有 verified 不被 unverified 覆盖——本条目模型工具本就不可设 verified）。
2. **验证状态枚举冻结**：`unknown`（迁移默认值：旧记录无从判断）/ `unverified`（已登记、未独立验证；解析器产出与手工登记的默认）/ `verified`（仅独立验证流程可置，归 R09 verify 条目；**state_add_\* 工具与 apply_facts 均不接受 verified 值**，索引层 add_vuln/add_cred 对 verified 抛 ValueError 做纵深防御，模型自述不升级）。severity/confidence 可缺失，缺失不臆造。
3. **schema v3 迁移**：vulns 增列 source TEXT、evidence_refs TEXT（JSON 数组）、verification_status TEXT NOT NULL DEFAULT 'unknown'、observed_at TEXT、reproduction TEXT；creds 增列 evidence_refs TEXT、verification_status TEXT NOT NULL DEFAULT 'unknown'、observed_at TEXT（source 已有）。hosts/ports 不加列——库存表非「发现」，其登记来源隐含为工具调用本身（取舍记录于此）。迁移机制：`Index.__init__` 在 executescript 后用 `PRAGMA table_info` 探测缺列，`ALTER TABLE ADD COLUMN` 逐列幂等补（SQLite 约束：新增 NOT NULL 列须常量默认），ALTER 序列经 `_transaction()` 单事务执行（executescript 会隐式提交先行事务，不能包它），失败回滚保留原库可读的 v2 状态；下次打开自动重试（AC06 中断可恢复）。迁移前一次性备份 `index.sqlite.pre-v3.bak`（存在则不覆盖；备份后打开快速读校验，备份权限钉 0600）；meta 版本只升不降沿用，版本号 UPDATE 在迁移提交之后（列已补齐、版本未升的半成品状态重开自愈）。旧程序兼容：v2 程序显式列名 INSERT 对新库不受影响（新列可空或有默认），照 test_state.py:1174-1211 模板做反向兼容测试。
4. **record_id 契约**：登记工具返回 `{record_id: "vulns/3"}` 形态（表名/行 id，行 id 库内稳定）。重复请求返回同一 record_id 并附 `deduplicated: true`。vuln/cred 的 created 判定由索引层返回值扩展为 `(id, created)` 承载；host/port 不改 upsert 签名，工具层用 query 白名单预查判定。
5. **证据引用校验（R08-A 核心）**：state.py 抽共享 helper `_resolve_contained_file`（state_add_loot 一并迁移复用，消除其 TOCTOU 窗口；`added: False` + 错误文案子串兼容既有测试）：入参相对或绝对路径 → `(root / ref).resolve()` → 须 `is_relative_to(root)`（拒 `..` 与指向 engagement 外的符号链接；指向内部的符号链接允许）→ `os.open` + `os.fstat` 绑定实际打开文件：必须 S_ISREG（拒目录）、fstat 与 `os.stat(resolved)` 的 (st_dev, st_ino) 一致（防检查/使用间替换）、size 取 fstat 值 → 关闭 fd。入库统一存相对路径字符串。残余微窗口（无 openat2/RESOLVE_BENEATH 的 POSIX 固有限制）如实写入 §8。evidence_refs 逐条校验，任一失败整体拒绝并在错误中指出哪条。
6. **四个登记工具（R08-B）**：state_add_host(ip, hostname?) / state_add_port(host, port, proto?, service?, product?, version?) / state_add_vuln(host, kind, title, evidence_refs?, confidence?, verification_status?, observed_at?, reproduction?) / state_add_cred(host, username, secret, evidence_refs?, sensitive?, verification_status?, observed_at?)。复用现有 upsert/add 写路径（事务语义沿用）；vuln 的 evidence_refs 校验后入库，同时回填 legacy evidence_path 列为首个 ref（报告旧渲染兼容）；cred secret 完整落盘（红线不变），工具返回不含 secret 原文（仅掩码形态）。observed_at 默认当前 UTC ISO，可由参数覆盖（ISO 字符串，工具层不做格式强校验——落库原样，回放展示原样；取舍见 §8）。注册进 TOOL_SCHEMAS（additionalProperties: False，描述写清掩码/验证状态语义）；cli/tui 的 register_module 自动覆盖无需改。
7. **解析器接同一模型**：parse.py vuln/cred fact 增可选 source/evidence_refs/verification_status/observed_at 键；sqlmap/nikto vuln 改填 evidence_refs=[output_path]（evidence_path 旧键保留兼容）+ source=工具名；hydra cred 填 evidence_refs=[output_path]（有 output_path 时）；**偏差**：sqlmap-dump cred 的证据是 dump CSV 本体（stdout 日志不含这些凭据），填 evidence_refs=[csv_path]（有 output_path 时再追加），而非决策字面量的 [output_path]——以证据真实性为准。apply_facts 映射新列，facts 未带时默认 source="parse"、verification_status 缺省由索引层新行默认 'unverified' 承载。解析失败回退路径不变。快照测试（test_parse.py 逐字锁 facts）相应更新并留痕。
8. **报告与展示（R08-C）**：vulns 节增显示 来源/验证状态/observed_at/evidence_refs（逐条列出，缺字段显示「未标/unknown」不臆造；仅有 legacy evidence_path 的行保持旧「证据：」行格式不变）；creds 节全值契约与红线标识**不变**；新增 `build_report(root, *, redact=False)`——redact=True 时 creds 节标题改「凭证(脱敏分享视图)」、secret 经 mask_secret（replay 复用 tools.state 的同一掩码函数，口径不漂移）、节首标识调整为分享口径，其余章节不变；`foam report` 增 `--redact` flag（cli.py 漂移，理由：分享视图的入口在 CLI，不在规格候选清单内但属 AC05 导出面的必要一半）。creds 缺元数据时掩码行为不变不泄漏原文（AC05）。统计节不动。attack_surface 显式列名维持不变（LLM 汇总面不扩字段，取舍记录；verification_status 经 state_query(kind="vulns") SELECT \* 已可达）。
