## 1. 问题、目标与边界

来源：[路线图](../roadmap/2026-09-25-release-roadmap.md)、[评估报告](../reviews/2026-09-25-repository-and-ux-assessment.md)。
评估代码基线：`3a9d07c7da9130e99681a48b5c8975b84b511492`。历史复现是设计输入，不作为本条目已修复证据。

- **来源与依赖**：旧维护批 8；依赖 R06/R07。
- **交付**：受控登记 host/port/vuln/cred；复用现有索引去重；每条发现含来源、证据引用、验证状态、时间、可选复现步骤。新字段作为明确 schema 迁移，旧记录缺失默认 unknown，不将 note 或模型自述直接升级为 confirmed。
- **范围/候选文件**：`src/foam/state/index.py`、`src/foam/tools/state.py`、`src/foam/tools/parse.py`、`src/foam/agent/prompts.py`、`src/foam/replay.py`；索引/工具/解析/报告测试。
- **排除**：不让模型定义自己的授权范围；不把“0 条登记”写成“未发现漏洞”的完整性保证。
- **风险与回退**：目标凭证属于敏感成果，API 密钥仍只走环境变量。存储目录/数据库/转录采用仅本用户可读写权限；分享导出另走脱敏视图，不静默改变现有报告全值契约。

## 2. 依赖、架构与数据契约

前置依赖：[R06](R06.md)、[R07](R07.md)

拟议 state_add_host/port/vuln/cred 复用现有 Index 的 upsert/add 接口，返回稳定 record_id。发现新增 source、evidence_refs、verification_status、observed_at、reproduction；severity/confidence 可缺失，模型声明不直接等于 independently_verified。

技术栈：Python/asyncio，沿用仓库 SQLite、PTY、Textual 与后端协议；新增模块仅在下述职责确有需要时建立。

### 全局约束

- Python ≥3.12、asyncio；标准库优先，新增依赖须说明理由，不引入重型框架。
- 仅服务明确授权目标；不为测试放宽 scope；API 密钥只走环境变量，fixture 使用 example.com/TESTONLY 等明显合成值。
- 运行产物与真实凭据不提交；历史审计链不重写；旧字段未知不等于零或已验证。
- 本文是规格与实施计划草案；用户此次授权编写文档，不代表授权所有功能实施。
- 后续按 AGENTS.md §7 一次推进一个条目/独立分片；使用 executing-plans 逐步执行，未决授权语义先裁定。

1. **去重键冻结**：vulns=(host_id,kind,title)、creds=(host_id,username,secret) 既有自然键不变；不做任何模糊相似合并（规格红线）。重复登记返回同一逻辑实体（同一 record_id）；证据 refs 并集追加不丢（read-modify-write 在单事务内，复用 `_transaction`，add 路径事务感知以兼容 consume_job_exit 的既有外层事务）；verification_status 不可经登记路径降级（已有 verified 不被 unverified 覆盖——本条目模型工具本就不可设 verified）。
2. **验证状态枚举冻结**：`unknown`（迁移默认值：旧记录无从判断）/ `unverified`（已登记、未独立验证；解析器产出与手工登记的默认）/ `verified`（仅独立验证流程可置，归 R09 verify 条目；**state_add_\* 工具与 apply_facts 均不接受 verified 值**，索引层 add_vuln/add_cred 对 verified 抛 ValueError 做纵深防御，模型自述不升级）。severity/confidence 可缺失，缺失不臆造。
