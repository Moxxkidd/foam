## 1. 问题、目标与边界

来源：[路线图](../roadmap/2026-09-25-release-roadmap.md)、[评估报告](../reviews/2026-09-25-repository-and-ux-assessment.md)。
评估代码基线：`3a9d07c7da9130e99681a48b5c8975b84b511492`。历史复现是设计输入，不作为本条目已修复证据。

- **来源与依赖**：旧平台批 14、初次启动排障；依赖 R03/R05（均已完成）。原规格写于 R11/R12 之前，2026-11-12 按已落地的 R02 锁、R09 只读证据、R11 执行边界和 R12 终态语义修订（§2.1）。
- **问题**：
  1. 首次启动排障只能读源码或试错：`load_config` 对坏 JSON/非对象静默返回 `{}`，用户不知道 profile 为何不生效；缺 key、base_url 缺失要到 run 装配才报错；protected 不可用的原因（平台/euid/解释器路径不可信）只在启动 run 时暴露。
  2. 不开 TUI 无法判断一个 engagement 是在跑、卡住、已中断可恢复、预算停止还是已结项；TUI 运行不持单写者锁（缺口由 [R28](R28.md) 修复），没有任何外部可观察的活性信号。
- **交付**：只读 `foam doctor` 与 `foam status <dir>`，人读与 `--json` 两种渲染同源；运行端写独立心跳快照供 status 判断活性。doctor 默认不发任何网络请求；网络探测只在显式 `--online` 下执行（范围见 D2）。
- **排除**：
  - 不自动修复、装包、写/迁移配置，不调用 `recover_stale` 等带清理语义的函数。
  - 不做 LLM 补全探测与后端支持矩阵（归 R21）；不做工具版本探测、可运行性判定与盘点缓存（归 R23），doctor 只复用现有 `scan_tools` 结果。
  - 不做 TUI 任务列表/恢复入口与 TUI 单写者锁（归 R15）；不做 UI 细粒度过程状态模型（归 R16）。
  - status 不校验审计链完整性（归 `foam verify`），只读链尾作为线索并提示用 verify 核验。
- **风险与回退**：心跳为独立快照文件，不每秒重写业务 metadata；PID/时间戳/心跳仅作运行状态线索，不作为审计可信证明。回退为移除两条子命令与心跳写入；残留心跳文件对旧版本无影响（§7）。

### 2.2 诊断结果契约

拟新增 `src/foam/diagnostics.py`，doctor 与 status 共享：

- `Check`：`code`（稳定点分标识，如 `config.file`）、`status`（`pass|warn|fail|unknown|skip`）、`message`（中文一句话）、`remediation`（中文可执行处置，pass/skip 可空）、`details`（结构化附加字段，仅允许非敏感值）。
- `DoctorResult` / `StatusResult` 为纯数据；`render_human` 与 `to_json` 只消费结果对象（AC07 同源）。
- 所有字符串字段在进入结果对象前统一经 `redact()`（§2.6），渲染层再做一次兜底，双保险。
- JSON 顶层带 `"schema": "foam.doctor/1"` / `"foam.status/1"` 与 `generated_at`（UTC ISO）；字段只增不改语义，破坏性变化升主版本号。

### 2.3 doctor 检查项（默认零网络）

| code | 内容 | 判定要点 |
|---|---|---|
| `python.version` | 解释器版本与路径 | <3.12 → fail |
| `foam.version` | `foam.__version__`、包位置、是否有分发元数据 | 元数据缺失 → pass 并注明「源码运行」 |
| `deps.<name>` | httpx/rich/textual 是否可定位及版本 | `importlib.util.find_spec` + `importlib.metadata`，不 import 目标包；缺失 → fail（textual 缺失注明仅影响 TUI） |
| `config.dotenv` | `./.env` 是否存在、注入的键名、畸形行号 | 只列键名，永不输出值；畸形行 → warn |
| `config.file` | `~/.foam/config.json` 严格只读检查 | 缺失 → pass（未配置）；坏 JSON/非对象 → fail 并说明「当前被静默忽略，profile 不生效」与修复方式；权限非 0600 → warn；含 key/token/secret 类字段 → warn（会被白名单丢弃，提示删除） |
| `config.profile` | `active_profile` 或 `--profile` 指名是否存在、backend 是否合法 | 指名不存在/非法 backend → fail |
| `backend.resolved` | 生效的 backend/model/base_url 及每键来源（flag/env/profile/default） | 复用抽出的纯解析函数；base_url 经 `sanitize_url`，失败显示占位符；openai_compat 无 base_url → fail |
| `backend.api_key` | 所选后端的密钥环境变量名是否已设置 | 只报「已设置/未设置」，不报长度或片段；未设置 → fail |
| `tools.inventory` | `scan_tools` 计数（可用/缺失/dpkg 是否可用） | 只复用现有探测（含 dpkg 超时）；工具缺失不 fail，地图仍是提示 |
| `workdir.engagements` | 默认 `engagements/` 或 `--workdir` 指定目录（与 run 同义，指 engagement 目录本身；不存在时检查父目录）的存在性、可写性、属主与权限 | 仅 `os.access`/`stat`，不建目录、不写探针文件 |
| `exec.protected` | protected 是否可用及原因 | 非 Linux / euid≠0 / 解释器或 helper 路径不可信 → warn 并说明「仅 legacy 可用」，处置指向 [R29](R29.md) 定案的受支持安装形态；不自动 sudo |
| `exec.stale_boundaries` | `/run/foam/network` 下形如边界 id 的残留目录数量 | 仅 Linux 只读列举；>0 → warn，说明下一次 protected 创建会自动对账；无权限读取 → unknown |
| `online.base_url` | 仅 `--online`：对生效 base_url 的连通性探测（范围见 D2） | 未给 flag → skip；超时/拒绝/TLS 失败 → fail，带处置 |

CLI：`foam doctor [--json] [--online] [--profile NAME] [--backend B] [--model M] [--base-url U] [--workdir DIR]`。后端相关参数沿用 run 的解析口径，仅用于「如果这样启动会解析成什么」，不构造后端对象。

### 2.4 status 契约（双轴：运行结局 × 进程活性）

`foam status <dir> [--json]`。只读来源：`engagement.json`（直接解析）、`audit.jsonl` 链尾（从文件末尾有界回读，不全量加载、不校验链）、`evidence/` manifest、`index.sqlite`（`_open_index_ro`，仅计数）、心跳快照（§2.5）。

- **run_state**（来自持久记录）：`closed`（meta closed）、`stopped`（链尾 `run_finished.status=stopped`，如预算停止，`goal_status=unfinished`，提示用 resume 显式扩容）、`interrupted`（meta active 且链尾无对应 `run_finished`，或为 killed/error，提示可 resume）、`active`（meta active 且活性为 alive）、`unknown`（meta 缺失/损坏/不可读）。
- **liveness**（来自心跳 + 进程身份）：`alive`（身份匹配且心跳新鲜）、`stale`（心跳超过过期阈值，或身份无法在本平台确认但心跳曾声明运行）、`gone`（心跳终态 `closed` 的正常退出、PID 不存在、身份不匹配即 PID 复用、boot 标识变化）、`unknown`（无权限读取、时钟异常即 `updated_at` 在未来超过容差、心跳损坏）、`none`（无心跳文件，旧版本 engagement 或从未以 R13 之后版本运行）。
- 任何情况下仅凭 PID 存在不得判 alive（AC05）；`stale`/`gone` 时 run_state 不得显示「运行中」。
- 输出附带：目标摘要、scope 来源与 sha256 前缀、创建/结项时间、最近活动（心跳 `last_activity` 与链尾记录时间取较新者并标明来源）、R12 预算 closing 快照（若有）、manifest 是否存在、发现/凭证/loot 计数、下一步建议（resume / verify / 已结项）。
- 不发任何 LLM 或网络请求（AC06）；不取锁、不改权限、不写任何文件。

### 2.5 心跳快照契约

拟新增 `src/foam/state/heartbeat.py`：写入端 `HeartbeatWriter`，读取端 `read_heartbeat` 与平台进程身份函数。

- **位置与权限**：`<engagement>/heartbeat.json`，0600，同目录 tmp+rename 原子替换；不 fsync（线索非证据）。protected 模式下由 root 控制进程写入，非 root 读取得到 `unknown` 并提示以运行用户查看（engagement 目录本身已为 0700）。
- **字段**：`schema="foam.heartbeat/1"`、`run_id`、`entry`（`cli-run|cli-resume|tui`）、`pid`、`proc_start`（平台进程启动标识）、`boot_id`（Linux `/proc/sys/kernel/random/boot_id`；macOS `kern.boottime`；取不到为 null）、`platform`、`started_at`、`updated_at`（UTC ISO）、`interval_s`、`seq`（单调递增）、`loop_status`（observer `on_status` 最近值，终态写 `closed`）、`last_activity`（`kind` ∈ `status|model|tool_call|tool_result`、可选工具名、`at`）。
- **不记录**：命令行、工具参数、模型文本、scope 内容、任何可能含凭据的字段。
- **写入时机**：装配完成后首写；`on_status` 变化与工具调用起止即时写（≥1 s 限流）；模型流式期间只置标志，由周期任务合并写入；周期任务每 `interval_s=10` 秒写一次；`close_run` 在释放锁前写终态 `loop_status=closed`。
- **失败语义**：写失败只记一次 warning，不影响 run、不进入审计链、不改变退出码。
- **过期阈值**：`max(3 × interval_s, 30 s)`；时钟容差 5 s。
- **进程身份**：Linux 用 `/proc/<pid>/stat` starttime + boot_id（复用 `_process_is_active` 口径并排除僵尸）；macOS 方案见 D3；其他平台身份不可确认 → 依心跳新鲜度给 `stale`/`unknown`，不给 `alive`。写入端与读取端使用同一函数取身份，保证自洽。

### 2.6 脱敏

- 统一 `redact(text)`：先把当前进程环境中已知密钥变量（`FOAM_LLM_API_KEY`、`FOAM_ANTHROPIC_API_KEY` 及 `FOAM_*` 中名含 KEY/TOKEN/SECRET/PASSWORD 者）和 `.env` 中同类键的**值**做字面替换为 `<已脱敏>`，再对文本中所有 URL 剥离 userinfo、敏感 query 打码（复用 `sanitize_url` 口径，解析失败整段替换为占位符）。
- 覆盖面：`message`、`remediation`、`details` 全部字符串、异常文本（`str(exc)` 先脱敏再入结果）、stderr 错误行。
- 密钥值无论长短一律整体替换，宁可过度脱敏也不保留片段；不输出哈希、长度或前后缀。

### 2.7 输出与退出码

| 命令 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| doctor | 无 fail 且无 unknown（warn/skip 允许） | 存在 fail | 参数/用法错误 | 无 fail 但存在 unknown |
| status | 读出状态（无论 run_state 为何） | — | 目录不存在或不是 engagement | meta 不可读或 liveness/run_state 关键字段为 unknown |

`--json` 时 stdout 只含一份 JSON；`.env` 注入提示与错误行一律 stderr（与 verify 一致）。
