语义决策（2026-10-05 定案；任何一项都不把授权扩大到不同的真实目标）：

1. **URL 判定 = 规范化 origin + suffix 前缀**。origin：scheme 小写；host
   小写、去尾点；IP 字面量（v4/v6）经 `ipaddress` 归一（`::1` 与
   `0:0:0:0:0:0:0:1` 同一）；有效端口 = 显式端口，缺省按 http=80/
   https=443 归一，未知 scheme 无缺省值。suffix 取 path+query+fragment，
   使新允许集除第 2 条所列同-origin 规范化外是旧字符串前缀语义的**子集**
   （query/fragment 照旧参与比较；规则 suffix 为空串即授权整个 origin，
   与旧行为相同）。路径前缀维持既有语义，不改目录边界匹配，不做百分号
   编码规范化（可能扩大授权，歧义即拒绝方向）；不新增 DNS 解析。
2. **规格认可的同-origin 归一放宽**（仅到同一真实 origin，永不跨
   origin）：大小写、尾点、IPv6 压缩/展开形态、缺省端口双向归一、目标
   URL 携带 userinfo 指向已授权 host（userinfo 凭据不属于 origin）。
   E01 点名的相邻域名与 userinfo 指向他站均为不同 origin，一律拒绝。
3. **畸形输入 fail closed**：目标 URL 端口非数字/越界、空 host、
   authority 不可解析（含不配对 IPv6 括号）→ 拒绝，不向调用方抛异常、
   不回退 host 检查；畸形 URL 规则由 `parse_scope` 在加载期抛
   `ValueError`（与既有「无法识别的规则」同一路径）。经全仓核对，
   无既有测试或示例 scope 依赖旧的宽松收下，无接口漂移需消解。
4. **nmap 范围 = 四八位组区间的笛卡尔积**，须被 scope 的 IPv4 CIDR 并集
   完整覆盖：区间合并 + 逐空隙 O(1) 命中判定，总 O(#CIDR)，不逐 IP
   枚举；倒置区间、越界八位组、前导零八位组（inet_aton 八进制歧义）
   均不作范围解析；v6 CIDR 不覆盖 v4 地址。新判定严格不宽于旧：hull
   两端属于请求集合，旧拒绝 ⟹ 新拒绝。
5. **遗留漂移（不在本条目提交范围，建议后续小条目跟进）**：
   `src/foam/agent/scope_compiler.py` 内嵌的编译器 system prompt 仍描述
   「字符串前缀语义，凡以该串开头的 URL 都在范围内」——该描述比修复后
   的实际执行**更宽**（fail-closed 方向，不构成新漏洞）；round-trip
   门禁天然吸收 `parse_scope` 的新严格性（`ValueError` →
   `ScopeCompileError`，无崩溃）。该文案修正需单独提交，本次未动。
   `src/foam/agent/prompts.py` 经核对为参数级通用表述，与新行为无矛盾，
   未改动；`tests/test_prompts.py` 快照原样通过。
6. **规则侧 userinfo 加载期拒绝（2026-10-05 对抗评审收口）**：初版实现
   对规则里的 `user@` 静默归一丢弃，`https://user@example.com/` 会按裸
   origin 授权——旧字符串前缀语义下该规则只匹配字面开头，新行为更宽，
   违反 §1「规范化不得扩大规则」。现 `parse_scope` 对
   `username`/`password` 非 None 的 URL 规则（含空 userinfo
