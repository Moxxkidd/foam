# R30 · protected 执行能力扩展评估（raw 扫描与入站回连）

状态：暂缓（2026-11-12 由 [R13–R27 方案评估](../reviews/2026-11-12-r13-r27-plan-review.md) F5 提出）。目标版本：[暂缓清单](../releases/deferred.md)，未分配版本。风险：高（涉及能力授予与网络边界）。负责人：待定。
优先属性：暂缓 / 研究。实施状态：未开始。

## 问题与范围

- **来源**：[R10](R10.md) §6 与 [R11](R11.md) 明确 protected 只支持出站 L3/L4 白名单与回复方向的 established 流量。以下 Kali 常见工作流在 protected 下不可用：
  - raw socket / AF_PACKET 类扫描：`nmap -sS/-sU/-O`、部分 masscan/arp 工具；
  - 入站回连监听：反弹 shell、`nc -lvnp`、Metasploit handler；
  - scope 中的主机名、通配域和 URL（protected 只接受 CIDR）。
- **影响**：用户遇到上述需求只能回到 legacy（参数级护栏、无网络强制），protected 的实际使用面被压缩。[R22](R22.md) 的 MS2 等场景也受影响。
- **目标**：用真实使用证据衡量上述限制的影响，再逐项评估能否在不削弱隔离与 scope 护栏的前提下提供受控能力，例如为指定工具授予最小 capability、受控入站端口映射、域名解析绑定。没有证据就保持现状。
- **排除项**：不为兼容恢复 root/raw/全部 capability；不允许宽放 established/related；不把域名授权退化为更宽的 IP 授权（R10 §6 约束继续有效）。
- **依赖**：R11（完成）；[R14](R14.md) R14-D 先让失败可解释并积累证据；R22 提供场景影响数据。

## 进入条件

1. R14-D 落地后，真实 protected 运行中这类失败有可归因的统计：分母、工具、频率、用户随后是否被迫切到 legacy。
2. 每项能力扩展都有独立的威胁分析与故障场景，并由用户明确纳入版本。
