## 2. 依赖、架构与数据契约

前置依赖：[R03](R03.md)、[R04](R04.md)

拟议终态事件包含 event_id、run_id、job_id、reason、exit_code、output_refs、ended_at；稳定事件 ID 贯穿审计、解析与消费进度。即时返回 running 不是终态。持久消费记录与事实写入在同一索引事务中提交，审计事件用稳定 ID 对账。

技术栈：Python/asyncio，沿用仓库 SQLite、PTY、Textual 与后端协议；新增模块仅在下述职责确有需要时建立。

### 评审记录（2026-10-08，实施前技术定案）

结论：**就绪**。对照 HEAD `ed30e64` 当前代码逐条核实后定案如下，分片按此实施；实施中若定案与代码事实冲突，以代码事实为准并在本节追加偏差。

- **决策 1（事件生产）**：bash.py 新增 `JobExitEvent`（dataclass：event_id/run_id(None 由消费方填)/job_id/command/reason/exit_code/duration_ms/ended_at(UTC ISO)/manifest 引用 output_path+sha256+stdout/stderr 路径与哈希+total_bytes/total_lines/error）。`BashTool` 增可选回调 `on_job_exit: Callable[[JobExitEvent], None] | None`，同步调用、由消费方自行调度异步任务。`_supervise` 在 finalize 之后、`done.set()` 之前触发；`_supervise_guarded` 兜底路径同样触发；回调异常捕获进 `job.error` 不影响 done 置位。每 job 恰触发一次（job 上加发送标志；finalize 幂等保证 manifest 稳定）。
- **决策 2（event_id）**：`f"job_exit:{job_id}"` 确定性派生，重复通知/重放天然同 ID。
- **决策 3（消费，loop.py）**：AgentLoop 装配时若 bash 与 index 都在，接线 `bash.on_job_exit = self._schedule_job_exit`（补 run_id、建消费任务入任务集）。`_consume_job_exit`：(a) Index 单事务 INSERT OR IGNORE `job_events` 行（event_id PK，含 job_id/run_id/reason/exit_code/ended_at/output_refs JSON/parse 结果列/consumed_at/audit_seq NULL）+ 若插入成功同事务 apply facts；(b) 提交后 append 审计 kind `job_exit`（audit.py 新增 `KIND_JOB_EXIT` 常量并入 KNOWN_KINDS），payload 含 event_id 全程对账；(c) 回写 `job_events.audit_seq`（独立小事务）。重复投递（INSERT 未生效且 audit_seq 非 NULL）→ 直接返回 duplicate，不动 facts 不动审计。崩溃于 (b) 前：audit_seq NULL → 重放补审计，可能产生同 event_id 的可辨识重复审计行（本规格 §7 明确允许，禁止虚称恰好一次）。解析失败走既有 `maybe_parse` 的 `parse_fallback`，原始产物不动，事件照常消费（facts 空、记原因）。
- **决策 4（schema v2）**：index.py 增 `job_events` 表（纯追加 CREATE TABLE IF NOT EXISTS），`SCHEMA_VERSION` 升 2；旧库（v1）打开自动建表并升 meta；v0.1.2 旧程序读写新库不受影响（SQLite 忽略未知表、DDL 幂等、meta INSERT OR IGNORE 不回退版本）——两个方向均须测试。新增 `Index.consume_job_exit(...)` 事务方法：显式 BEGIN/COMMIT 边界，内部复用 upsert 逻辑但事务内不各自 commit（公开 upsert 方法的 commit 抽成事务感知的私有提交点，既有公开签名/语义不变）。Busy（报告快照期）如实失败：事件保持未消费（pending），不静默丢。
- **决策 5（run_id）**：AgentLoop 增 `self._run_id = uuid4().hex[:12]`；`run_started` 与 `job_exit` payload 携带（纯追加字段，重放兼容）。
- **决策 6（排空，R06-C）**：`AgentLoop._finish` 在收割完成后、append run_finished 之前 `await self.drain_job_exits()`（gather 消费任务集，有界超时默认 5s 常量；超时未完成的事件以 status="pending" 落 job_events 行明确登记，报告进 run_finished 载荷）。审计顺序钉死：job_exit* < run_finished <（kill 路径）kill_switch 仍在 run_finished 前。`runtime.close_run` 增可选 keyword 参数 `drain: Callable[[], Awaitable[None]] | None = None`，在收割步骤后、state.close 前 await（异常记 errors 不跳后续）；未显式传入时从 `runtime.loop` 兜底获取 `drain_job_exits`（CLI/TUI 调用点不改——见下方偏差注记）。drain 后清空接线（`bash.on_job_exit = None`）；索引已关闭后迟到的消费任务捕获 sqlite 已关异常，不碰已关索引（pending 登记已在 drain 内完成）。
- **决策 7（范围外）**：不注入模型消息流/TUI 通知（模型仍经 list_jobs/read_output 感知结果）；不恢复进程崩溃时孤儿 job 的事后重建（归 resume/恢复条目）；`exec_result_meta` status=running 的即时返回记录保持不变（终态由 job_exit 表达）。
- **决策 8（后台 exec_result_meta 不双写）**：即时返回的 running 记录保留现状；终态只出 job_exit，不再补 exec_result_meta 终态版（避免双事实源）。

**接口漂移注记**：本规格 §3/§4 写于 runtime.py 存在之前（当时收尾协调假定在 loop/cli 内）。实际 R03 已落地 `foam/runtime.py` 统一关闭面，故 drain 挂点改为「loop `_finish` 主排空 + `close_run(drain=...)` 兜底」两层；`output.py` 无需修改（finalize/manifest 能力已齐备）；`parse.py` 不新增接口（`maybe_parse`/`apply_facts` 原样复用，事务内不 commit 由 index.py 的事务感知提交点承担）。CLI/TUI 的 `close_run` 调用点本条目不改（保持既有调用签名），由 close_run 内部从 `runtime.loop` 兜底取得 drain——若后续条目需要显式接线可在调用点传入，行为等价。
