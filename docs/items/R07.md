### 2026-10-09 实施前评审与定案（对照 e115aef 代码核实）

**结论**：规格与当前代码事实一致，无规格级阻塞；依赖 R03（资源/事件约定、aclose 幂等有界）与 R06（run_id 先例、KIND 注册范例）已落地。评审通过，条目就绪并即日开工。

**代码事实核对**（e115aef，逐项与规格假设比对一致）：

- `session.py` 五操作统一 error dict 形态，唯一例外 `session_open` spawn/`connect_read_pipe` 失败 raise（:417-436），穿过只捕 TypeError/ValueError 的 `registry.dispatch` 上抛，`run()` 以 error 终结；`session_send` 无任何审计。
- `_detect_prompt`（:738-756）：`bytes_total == last_event_offset` 不重报；事件 dict `{type, prompt_type, text, hint, offset}` 追加 `session.events`，read 时排空（:578-579）；`_reader_loop` 每 chunk 触发检测（:724）。
- 转录走 OutputRecorder split=False 单文件 `{session_id}.log`，构造即建文件（output.py:84），无 chmod（权限随 umask）。
- `loop.py::_execute_tool`（:839-876）无 session 分支；`self._run_id`（:465）；`audit` 为构造必传参数；`run()` 的 CancelledError 路径（:551-565）经 `_finish` 写 `run_finished(status=cancelled)` 后重抛。
- `audit.py` KNOWN_KINDS（:56-70），R06 KIND_JOB_EXIT（:54）为注册范例；append 立即 flush；`test_all_known_kinds_roundtrip` 自动覆盖新 kind。
- `replay.py` format_record 未知 kind 走通用兜底（:265-267）不炸；audit_stats 七项计数；report「操作员插话记录」专节（:558-570）为范例；legacy 先例 `test_audit_stats_legacy_chain_refusals_zero`（旧链真链构造）。
- `bridge.py` ToolCallMsg 丢弃 call.id（:163）；`tool_call_display` 对非 run_command 工具显示紧凑 JSON 截 96 字符（:141-144）——session_send 的 text（口令）以明文上卡头，确为 AC04 要堵的面；ToolCard 展开体只渲染 result（build_card_body），不含调用参数；`widgets.py::summarize_result("session_send")` 只显示「已写入 s-xxx」（:267-268），无敏感面。

**定案决策**：

1. **`session_op` 审计 kind**：audit.py 注册 `KIND_SESSION_OP = "session_op"`。loop `_execute_tool` 增 session 分支（`call.name in {session_open, session_send, session_read, session_close, session_list}`），dispatch 前后包 try：正常返回 `outcome = "error" in result and "error" or "ok"` 落一条；CancelledError 落 `outcome="cancelled"` 后原样重抛（sync append，取消安全）；其他异常（spawn raise）落 `outcome="error"`（error=类名+消息）后原样重抛——不把异常当作没执行，但不改变 raise 终结 run 的既有行为（记为边界）。payload：op_id（uuid4 hex[:12]）/run_id/call_id（call.id，provider 原生）/op/session_id（open 从成功结果取，send/read/close 从参数取，失败/列表可为 None）/outcome/duration_ms/ended_at + 分类元信息：open 记 command（与 exec_request 明文同暴露级）；**send 只记 bytes（text 参数的 utf-8 编码长度，不含自动补尾换行），绝不记 text 原文或 text 的任何 hash**；read 记 new_bytes/cursor/has_more/matched/timed_out/events_drained 数（仅 outcome=ok 时；error dict 无这些字段）；close 记最终 status；list 记 count；error 时记 error 消息（工具 error dict 的消息本就面向 LLM，无敏感参数）。每个调用一条记录，调用/结果在同一条内成对可对账。**read/list 不聚合**（逐条最可核验；链 append 实测 10k<1s，成本可忽略；规格「允许聚合」是许可不是要求——此处选择逐条）。
2. **`session_prompt` 审计 kind**：`KIND_SESSION_PROMPT = "session_prompt"`。session.py 增可选回调属性 `on_prompt: Callable[[str, dict], None] | None`（默认 None；参照 bash 层 `on_job_exit` 先例），`_detect_prompt` 追加事件时同步触发（回调异常捕获不破坏 reader loop）。loop 装配时若 session 在场则接线（audit 为构造必传）：回调 → `audit.append(session_prompt, {run_id, session_id, pattern_kind(=事件 prompt_type), transcript_offset(=事件 offset), prompt_text(截断 200 字节), hint})`。**检测时落链**（不依赖 LLM 发起 read），生成一次落一条，read 排空不重复落。LLM 面向的事件 dict 字段名（prompt_type/offset）不动以稳线格式，审计侧采用规格字段名（接口漂移，见下）。prompt_text 是输出侧提示（如 "Password:"），非输入，可记。
3. **提示去重语义钉死而非重写**：现状即规格语义——同 offset（bytes_total 不变）不重报（AC02）；新 offset 相同提示产独立事件不丢（AC03）。不引入「同文本相近 offset」层面的额外去重（会违反 AC03）。
4. **敏感保护（AC04）**：(a) session_send 审计只记字节数（决策 1）；(b) TUI 卡头屏蔽：`tool_call_display` 对 session_send 的 text 参数替换为 `"***（N字节）"` 形态（bridge.py:141-144 处），其他参数照常；(c) 转录文件权限：session_open 创建 recorder 后将 `{session_id}.log` chmod 0o600（POSIX 语义，测试 stat 钉死 `st_mode & 0o777 == 0o600`）；bash 输出层不动（本条目只管会话转录这一敏感产物）。
5. **replay/统计（R07-C）**：replay.py format_record 增 session_op/session_prompt 分支（时间线可读：op/outcome/session_id/duration；prompt 显示 pattern_kind@offset）；audit_stats 增会话计数（`session_ops` 总数、按 `session_op:{op}:{outcome}` 扁平键分解、`session_prompts` 数）；新增 `session_coverage` 判定：链中无任何 session_op 记录 → `"legacy"`（显示「legacy（无会话审计记录）」，不是「0 会话」），有 → `"tracked"`。report 统计节同步展示。**不改历史链、不补写重算**。
6. **接线条件与退化**：loop 装配 `session.on_prompt` 仅当 session 在场（audit 为构造必传，恒在场）；无 loop（纯工具测试）会话行为完全不变。session_op 落点在 loop 层（session.py 不 import audit，保持 WP-05 分层）。
7. **范围外边界**：session_open 不过 scope 护栏的现状不改（规格排除项：审计补齐 ≠ PTY 授权检查已解决——此处明示记录此已知缝隙）；spawn 失败仍 raise 终结 run（现补审计可见；转 error dict 的行为变更不在本条目）；不向 TUI 实时推送 prompt 消息（侧栏 pending_events 轮询已可见；SessionMsg 属 UX 增强另议）；bridge ToolCallMsg 仍不带 call_id（仅审计侧关联）。
8. **审计明文扫描口径**：AC04 的合成口令扫描 = 用 TESTONLY 口令走完整 open→send→read 流程后，grep 审计 jsonl 全文与 TUI 卡头渲染输出，断口令字符串不出现（转录 .log 是敏感产物本体，靠 0o600 管理，不在扫描排除之外另作断言——它的内容本就可能含回显）。

**接口漂移**：

- 审计侧 session_prompt payload 字段名采用规格的 `pattern_kind`/`transcript_offset`；session 层 LLM 面向事件 dict 的 `prompt_type`/`offset` 不动。映射在 loop 回调内完成。
- `widgets.py` 不改动：session_send 结果摘要本就不含 text（「已写入 s-xxx」），卡头屏蔽在 bridge.tool_call_display 一处收口。偏离主 agent 授权中「widgets.py 若屏蔽确有需要」的条件分支——条件不成立。
- session_send 审计的 `bytes` 取 text 参数 utf-8 编码长度（请求侧），不含工具自动补的行尾；与结果侧 `bytes_written` 可能差 1，语义为「请求发送的字节数」。

**待决**：无规格级待决。决策 7 列出的四项边界（scope 不过会话、spawn raise 终结、TUI 无实时 prompt 消息、ToolCallMsg 无 call_id）为明示记录的范围外事项，不在本条目改动。
