## 迁移与回退

- 当前索引 schema 为 v4。可写打开索引时沿用既有逐版本迁移；v3/v4 列迁移
  分别在单事务内执行，失败回滚并可在故障排除后重试。迁移前一次性备份
  `index.sqlite.pre-v3.bak` / `.pre-v4.bak`，存在不覆盖并验证可读性。
- `report` 虽为报告命令，打开旧索引仍可能触发上述迁移和备份；只有
  `foam verify` 保证 SQLite `mode=ro`、不迁移、不取写者锁、不创建文件。
  pre-R09 终态没有 manifest 时显示 unknown/legacy（通常 rc 3），不补造历史
  证据；旧 schema 缺列的对应维度同样如实降级，而非假装 pass。
- scope/objective 修订按 R02 协议先落审计再提交 meta；旧格式首次修订前保留
  `engagement.json.pre-r02.bak`。显式 `resume --scope` 是重新授权，plain
  resume 恢复最近一次已提交范围并对账文件 hash。
- 内置备份用于迁移故障恢复和取证，不承诺任意旧包都能写新 schema。需要
  降级时先停止全部写者并复制整个 engagement；不要直接用旧程序写回新库，
  不要删除备份或改写审计链。代码回退不会自动降级数据库，兼容写入仅限
  各 R 文档已有实测的旧 schema 组合。
- 回退发布包不影响已经生成的 manifest/结项页；崩溃或 TUI 强制退出等未
  正常收口路径可能本无 manifest，应保留现场并用 verify 查看 unknown/pending。

## 公开能力边界

- **scope 不是全通道沙箱**：`run_command` 有命令级护栏，但 PTY
  `session_open`/会话输入不经过该检查，在途会话也不随 scope 热换获得网络
  隔离。网络层执行边界归 v0.2 的 R10/R11；本版本不得宣称已实现。
- **verify 不是漏洞验证器**：四维 pass 只表示所核验证据一致且覆盖无未知项。
  它不执行漏洞复现、不写 `verification_status`；`verified` 当前没有生产
  置位入口，登记/解析路径与模型自述均不能升级到 verified。
- **本地链不是外部不可抵赖**：截尾或整体重写不可检测，输出始终标明未外部
  锚定。界外/绝对路径 evidence_refs 不跟随、不打开；引用维只查界内存在性，
  不核验引用文件内容。session 转录没有终态登记 hash 时使用 manifest 时点
  快照，最新快照后的追加与篡改存在语义歧义。
- **终态与 meta 语义不同**：finished 将 engagement 置 closed；error/killed
  保持 active 以便恢复。verify 同时展示配对、pending、cleanup 与 manifest
  证据，不把 active 自身误判为仍运行。
- **报告脱敏范围有限**：默认报告含凭证全值；`--redact` 只脱敏凭证节，时间线、
  发现、笔记等其他章节未脱敏，外发前必须审阅全文。
- 真实模型、其他后端、裸 Kali 本轮未重新实测；历史实弹记录不等于本候选
  新增环境证据。TUI 同步生成 manifest 在大 engagement 收尾可能延迟；其他
  已知限制以各 R 文档 §8 和 [known-issues](../known-issues.md) 为准。
