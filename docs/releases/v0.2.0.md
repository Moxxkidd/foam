## 迁移与回退草案（R29-A）

本节是受支持安装形态的文档草案，尚未在真实 Kali 上从干净系统验证，不核销 R29 的真实 Kali 发布门槛。

- **legacy 不变**：既有 pipx/用户目录安装继续只用于 legacy；pipx 安装不支持 protected，因为用户可写的解释器或 helper 源路径不满足 R11 `_trusted_source` 的 root 所有、非组/他人可写判据。
- **迁移到 protected**：按 README「protected 安装」由 root 创建 `/opt/foam` venv 并安装发布 wheel；启动仅经 `sudo --preserve-env=FOAM_LLM_API_KEY,FOAM_ANTHROPIC_API_KEY,FOAM_LLM_MODEL,FOAM_LLM_BASE_URL` 传递四个白名单变量。不得使用 `sudo -E`、`--break-system-packages` 或 chmod/chown 等放宽权限的做法。
- **产物读取**：engagement 保持 root 所有、0700，不 chown 给调用用户；`report`/`verify` 使用同一 `/opt/foam/bin/foam` 经 sudo 执行。`status`/`doctor` 已由 R13-A/B/C 交付，其权限提示与只读诊断已有 R13 验收证据；真实 Kali 的 protected 安装与产物读取仍由阻塞中的 R29-B 验收。
- **配置边界**：Foam 读取当前工作目录的 `.env`，不是按 `HOME` 或 `/opt/foam` 查找；已存在的同名环境变量不被覆盖。sudo 后的 `HOME` 及 profile（`~/.foam/config.json`）究竟指向 root 还是调用用户，取决于系统/sudoers 配置，尚未在真实 Kali 实测；当前示例不依赖 profile。
- **回退**：停止使用 protected 并回到既有 pipx 安装的 legacy 路径即可；不自动删除 `/opt/foam` 或 engagement，也不通过 chown/chmod 改变 root 私有产物。回退不表示真实 Kali 的 protected 安装已验证或可发布。
