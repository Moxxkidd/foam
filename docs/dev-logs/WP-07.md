## 设计取舍

1. **「增强而非门槛」是全部架构的出发点**。`maybe_parse` 是唯一入口,
   三种结局:命中解析器返回 `ParsedOutput`、注册表未命中返回 `None`
   (常态,**不记审计**)、解析失败返回 `None` + `parse_fallback` debug
   审计(reason 区分 `no_match` / `exception`)。任何路径都不向 loop
   抛异常——本产品 bash 全开,LLM 用任何冷门工具都不被挡,解析器
   永远只是增强。
2. **二元组分工**:summary(≤500 字节,`cap_summary` 含省略号预算、
   不截半多字节字符)是 LLM 视图;facts 是原子事实 dict,经
   `apply_facts` 喂 WP-06 索引。两者严格分离——hydra/sqlmap 的 cred
   facts 带**完整 secret** 落盘(WP-10 报告可见),summary 一律掩码
   (复用 WP-06 `mask_secret`)。索引层拿全量、LLM 视图拿掩码,与
   WP-06 的 attack_surface 不含 secret 一脉相承。
3. **注册表形状与 WP-01 同构**:`PARSERS` dict + `@register("tool")`
   装饰器 + `maybe_parse` 单入口(相当于 dispatch),后续 WP 扩充解析器
   一行注册;loop 接线(在哪个钩子调 maybe_parse)不在本 WP 范围,
   接线后接上 prompts.py 里「自动入库由解析层后续版本提供」的占位。
4. **工具名识别**:命令首 token 的 basename;裸 `sudo`/`doas`/`env`
   包装跳一层。已知限制:`env FOO=1 nmap` 这类带赋值的 env 形式会
   派发为 `FOO=1` 未命中——按设计静默走通用路径,不算缺陷(对抗
   审查已驳回该项)。
5. **nmap 三格式容忍**:`-oX` XML 优先(stdlib `xml.etree`;S314 已
   noqa 注明依据:规格限定标准库、输出来自本地授权工具、Python 3.12
   捆绑 expat 默认抑制实体放大),XML 损坏落回 grepable/文本表格。
   grepable 路径处理真实 `-oG` 双行形态(`Status: Up` 行补录无开放
   端口的存活主机,Ports 行 rDNS 回填主机名)。
6. **facts 归属尽量落 IP**:nikto 输出自带 `+ Target IP:`,facts 挂
   IP 与 nmap 的 host 行合一(主机名经 host fact 挂到 IP 上),避免
   同一台机器在 hosts 表分裂成 IP 行 + 主机名行。
7. **sqlmap loot CSV(规格「stdout 关键段 + loot CSV」)**:从 stdout
   的 output 目录行定位,rglob 扫 dump CSV → 每份登记 loot fact;列名
   启发式(pass/pwd/hash + user/login)提 cred fact。目录不存在/读
   失败只丢 loot,绝不影响 stdout 注入确认(局部 try)。**信任假设**:
   该路径行由 sqlmap 自身打印(目标服务器无法控制其内容),指向本机
   sqlmap output 目录,属可信本地路径;文件系统访问控制不在本模块
   职责内。上限:20 份 CSV × 1000 行 × 每份 50 条 cred。
8. **apply_facts 的兜底语义**:非 dict 元素、缺字段、未知 kind、
   sqlite 约束/故障错误(如必填字段 None 触发 NOT NULL)全部归
   `skipped` 计数。DB 故障同样不抛——索引问题不该打断 loop,调用方
   用 stats 与 `Index.counts()` 对账即可发现。
9. **错误 facts 比丢失更糟**:sqlmap `Parameter:` 行不匹配时防御性
   重置 current_param(宁可丢该条注入,也不把后续 Title 误挂到上一个
   参数);nikto 的 SSL Info 证书元数据行进 skip 列表(不当漏洞进
   vulns 表);nmap 服务名修饰符清洗(`ajp13?`→`ajp13`、
   `ssl|http`→`http`)——索引服务列只放可查询裸名。

## 踩坑

1. **nikto skip 前缀吞行**:`"+ Target"` 宽泛前缀把 `+ Target Port:`
   一并跳过,端口永远 None。教训:头行过滤前缀必须带冒号精确到字段
   (`+ Target IP:`),同族前缀行是解析器开发的通用陷阱(已沉淀
   HANDOVER 陷阱 17)。
2. **cap 测试要真触发 cap**:原用例 gobuster fixture ×30 也只 ~180
   字节(亮点只列前 6 条,设计如此),cap 路径根本没走到。改为直测
   `cap_summary`(含多字节不截半、limit 边界)+ 注册自定义解析器经
   maybe_parse 验证。HANDOVER 陷阱 11「压缩/预算测试先算后写」的
   又一实例。
3. **repo 路径符号链接**(HANDOVER 陷阱 15 已记):诊断「编辑没
   落盘」前先 diff 两路径——`kali-code` 是指向 `foam` 的 symlink,
   内容恒等,所谓「落错目录」实为该次编辑本身未生效。
4. **`SplitResult.port` 是惰性求值**:`urlsplit()` 不校验端口,
   `http://host:abc/` 在访问 `.port` 时才抛 ValueError——try 块要包到
   属性访问,不是只包构造。
5. **ruff S314 与标准库红线**:规格限定只用标准库,defusedxml 不可
   用;按陷阱 8 格式 noqa(理由写上方独立注释),依据:解析对象是
   本地授权工具 stdout,Python 3.12 捆绑 expat 默认抑制实体放大。
