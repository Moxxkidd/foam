## 设计取舍(及对规格的有意偏离)

1. **哈希覆盖范围**:规格公式写作 `hash = sha256(prev_hash + canonical(payload))`,
   只覆盖 payload;但验收 4 要求「篡改任一记录任意字节,verify 必失败」——
   seq/ts/kind 若不入哈希,改它们不断链。故实现把 `prev_hash + canonical(
   {seq,ts,kind,payload,prev_hash})` 作为哈希输入,验收条款优先。
2. **fail closed**:`shlex` 分词失败的命令一律拒绝(无法校验即不放行);
   审计链末行损坏时拒绝续写(防止在可疑链上静默追加)。
3. **URL 判定是「或」语义**:URL 前缀命中 ∨ host 部分命中 CIDR/主机名/通配域,
   任一即放行。含义:scope 同时写 `127.0.0.0/8` 和 `http://127.0.0.1:3000/`
   时,`:4000` 也放行(/8 本来就覆盖);要端口级细粒度,scope 里就不能有更宽
   的 CIDR。`test_url_prefix_scope_is_port_specific` 固化了该语义。
4. **CIDR 目标用 `subnet_of` 判定**:命令写 `/16` 超网扫 `/24` 的 scope 会被拒,
   防「以更大网段绕过」。
5. **nmap 八位组范围**(`192.168.56.1-50`、跨段 `192.168.56-57.10`):端点凸集法
   ——范围是连续区间、scope CIDR 是凸集,两端在界内 ⟺ 整段在界内。这是开发中
   补的:nmap 是头号工具,范围语法不支持会被误拒成灾。
6. **提取多层兜底**:`TARGET_FLAGS`(`-h/-t/-u/-d/--target/--url/--host/...`)
   的值(宽容,收单段主机名)+ 任意位置的 IP/CIDR/URL/`user@host`/`host:port`/
   msf 风格 `KEY=VALUE` + 裸含点主机名。`KEY=VALUE` 只收 `RHOST/RHOSTS/TARGET/
   URL/...` 等攻击目标键,**不收 `LHOST/LPORT/SRVHOST`**(回连地址通常是攻击机
   自身,收了会频繁误拒)。
7. **误判抑制两层**:`FILE_VALUE_FLAGS`(`-oN/-oA/-w/-iL/-P/-L/-C` 等)的值跳过;
   裸位置参数中末段是常见文件扩展名(`.txt/.xml/.pcap/...`)的词视为文件名。
   `.zip/.mov` 是真实存在的 gTLD,刻意不收进扩展名表(防绕过)。
8. **裸单段词不提取**(`echo hello` 里的 `hello`):否则普通单词全被误判为
   越界主机名,工具不可用。代价是漏判面,见下。
9. **审计写入**:每条 `flush`(崩溃至多少尾条缓冲),不 `fsync`(1 万条性能
   实测 0.33s,fsync 会慢一到两个数量级)。LLM 内容经 `llm_meta` 只记
   sha256 与 token 数。
10. **无目标命令放行**:护栏只管网络目标,纯本地命令不在管辖内;含 `$`/反引号
    的命令不阻断,但 `warnings` 进审计 payload 留痕。

## 绕过面清单(如实;v0 是参数级启发式,不是网络层强制)

1. **shell 变量**:`ping $TARGET` / `${T}`——展开值不可静态校验(有 warnings 留痕)。
2. **命令替换**:`ping $(dig +short evil.com)`、反引号——同上。
3. **混淆编码**:`printf '\x38\x2e...' | sh`、`base64 -d | sh`、进制/拼接变形。
4. **文件/流间接目标**:`nmap -iL targets.txt`、`hydra -C combo.txt`、stdin 读目标
   ——护栏看不到文件内容。
5. **交互式工具内部状态**:`msfconsole` 里 `set RHOSTS x.x.x.x` 不经 shell 命令行;
   补救点在 WP-05 的 PTY 会话层(v0 未覆盖)。
6. **裸单段主机名漏判**:`ping metasploitable`(无点、无 flag)不提取。
7. **逗号/特殊分隔目标列表**:`nmap 10.0.0.1,10.0.0.2` 不拆逗号(nmap 主用空格
   分隔;如实际多用再补)。
8. **审计链截尾攻击**:删除末尾 N 条记录 verify 不可知(前向哈希只保历史不被
   改写);需外部锚定最新 hash,v1 立项。
9. **shlex 与实际 shell 的分词差异**边角(posix 模式)。
10. **DNS 语义**:护栏不做解析,主机名按字符串匹配;`evil.com` 解析到界内 IP
    仍按主机名规则判(偏严方向拒绝,不构成绕过,但属语义边界)。

## 误判案例记录(验收 2)

开发中实测撞出并已修复、固化测试的:

- `nmap -oN report.txt 192.168.56.10`:`report.txt` 被含点主机名规则误抓 →
  引入 `FILE_VALUE_FLAGS` 修复。
- `hydra -P pass.txt ...` / `-P passwords`:`-P` 未识别 → 加入文件 flag;
  无扩展名密码文件也靠 flag 跳过。
- `grep -rn 3.14 .`:版本号 `3.14` 形态像主机名 → 「纯数字点分不算主机名」。
- `ssh user@[2001:db8::1]`:`[v6]` 括号未剥 → 补括号处理。
- `nmap 192.168.56.1-50`:范围被当主机名误拒 → 补八位组范围支持。

仍存在的已知误判方向(接受并记录):

- 非常见扩展名的输出文件(如 `report.foo`)在裸位置会被当主机名拒绝;
  LLM 纠正说明会引导改用标准扩展名或调整写法,操作员也可在拒绝后介入。
- `.zip/.mov` 域名(真实 gTLD)在裸位置不校验(文件扩展名表与 gTLD 重叠的
  固有冲突,选择放行方向,记录于此)。
