## 设计决策

1. **resume 的恢复顺序与对账**(全部在同步 preflight 完成,ASYNC240
   合规):
   - objective:`--objective` 显式 > engagement.json > 审计链最后一条
     run_started(legacy 目录兜底)。
   - scope:`--scope` 显式(=重新授权,写新 scope_loaded 续链)>
     engagement.json 记录的原路径,**sha256 对账**——文件被改动则拒绝
     (exit 2,提示「如确为重新授权,请用 --scope 显式指定」)> 无
     engagement.json 时从审计链 scope_loaded 恢复,按
     cidrs/hosts/wildcards/url_prefixes 摘要逐域对账。
   - 目录不存在 → exit 2;**缺 audit.jsonl → exit 2**(审计链是 resume
     的唯一可信史);链断 → find_chain_break 报首个断点,exit 1。
   - legacy 目录(WP-04 时代,无 engagement.json)经 `Engagement.create`
     幂等修复布局后续跑——m1-demo 副本实测走通。
2. **resume 上下文 = 重建,不是全量回放**:system prompt 重建(授权声明
   含 scope 规则原文)+ ENGAGEMENT.md 当前全文(loop 每轮刷新机制天然
   载入)+ resume 简报一条 user 消息(`build_resume_briefing`:统计 +
   最近 N 轮动作窗口 + outputs 提示)。简报经 `loop.interject()` 注入,
   与操作员插话同一通道进审计。
3. **replay verify 先行**:任何回放前先全链重算;断链只报断点(行号 +
   记录 seq + 链上应为 seq + 原因),绝不回放不可信历史。
4. **report 降级矩阵**:无 engagement.json → 从审计链恢复 objective/scope
   并标注;无 index.sqlite → 各索引节标注缺失;链断 → 头部标「校验未
   通过」且不出时间线。任何缺件都不炸(m1-demo legacy 目录实测)。
5. **tui 占位约定**:`foam tui` 尝试 `from foam.tui.app import main`,
   ImportError 时报「TUI 尚未就绪」并写明入口约定
   `foam.tui.app:main(args)`,exit 2。WP-09 在飞,不等它——按此约定
   接线即可,零耦合。
6. **工具地图接线**(WP-08 留下的接口契约):`scan_tools()` →
   `render_tool_map(scan)` 传 `build_system_prompt(tool_map_text=...)`,
   `render_startup_line(scan)` 打启动一行;实测注入后 prompt 无占位文本。
7. **凭证全值只在 report**:报告生成直接读落盘 index.sqlite(WP-06
   契约),全值导出;LLM 视图全程掩码(state_query 语义不变)。
