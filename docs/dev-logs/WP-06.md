## 设计取舍

1. **upsert 语义**:hosts 按 ip、ports 按 (host_id, port, proto)、creds
   按 (host_id, username, secret)、vulns 按 (host_id, kind, title)、
   loot 按 path 去重;重复上报用 COALESCE 更新易变字段(非空新值覆盖
   旧值),notes 不去重(每条都是新观察)。解析器可以无脑重报,不会
   刷重复行。
2. **脱敏两层防线**:索引层 `attack_surface` 的 creds 汇总**只给
   username/source/sensitive,连 secret 字段都不查**;工具层
   `state_query(kind="creds")` 再过 `mask_secret`(头 2 + 固定 8 个
   掩码符 + 尾 2;长度 ≤4 全掩;掩码符数量固定,不泄露精确长度)。
   完整值只存在于落盘 index.sqlite(WP-10 报告经索引层 `query` 直取)。
   工具层不提供任何 reveal 参数——LLM 无法通过工具拿到完整 secret。
3. **attack_surface 作为 state_query 的扩展 kind**:规格工具只列
   kind+filters 形式,但「汇总某 host 攻击面」是 LLM 最高频需求之一,
   以 `kind="attack_surface", filters={"host_ip": ...}` 提供;filters
   缺 host_ip 时回 error dict 引导。
4. **通用 query 的注入防护**:filter 字段走 `QUERY_KINDS` 白名单(未知
   字段 ValueError),列名/表名/order by 全部模块常量,外部值一律
   参数化绑定;S608 字符串构造告警为静态误报,noqa 处已注明依据。
5. **create 幂等 + 冲突即错**:同参数重复 init 不动任何已有内容
   (ENGAGEMENT.md 的手写标记都保留);objective/scope 与已有
   engagement.json 冲突时 ValueError——防止两个 engagement 误用同一
   目录把状态搅在一起。
6. **scope 只存哈希不复制**:engagement.json 记
   `{path, sha256}`——事后可用哈希对账 scope 是否被改(WP-02 审计链
   思维);不复制文件本体,避免 scopes/ 与 engagement 内双源漂移。
7. **ENGAGEMENT.md 程序化重写**:update_progress 每次重写整个文件
   (meta 头 + 进展段 + 自动统计计数),文件由程序全权维护,保持小而
   可整载入 context;note 参数留给 loop 一句话自由段。
8. **同步实现 + async 薄壳**:状态操作全是毫秒级小 IO,实现方法为同步
   def(与 WP-01 `_render_view` 同模式),`dispatch` 为 async 以便
   WP-04 统一 `await`。
9. **state_add_loot 路径约束**:必须在 engagement 目录内
   (`is_relative_to` 防 `../` 逃逸),不存在则回 error dict 引导「先
   run_command 写入 loot/ 再登记」;登记存相对路径与 size_bytes。

   的 `ad`,实际 fixture secret 是 `TESTONLY-...` 头 2 为 `TE`——掩码
   行为本身正确,测试期望笔误。
4. ruff E501 连 SQL 字符串内的长行也计入行宽——DDL/SELECT 按多行
   排版。
