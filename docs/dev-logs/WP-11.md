## 设计取舍(任务一)

1. **钩子位置**:`_execute_tool` 内 dispatch 成功后、exec_result_meta
   落审计前——解析统计(`tool/summary_bytes/facts/facts_applied`)并入
   同一条审计记录,不新增审计 kind(fallback 走 WP-07 既有
   `parse_fallback`)。
2. **解析用文本**:落盘全文 ≤ 1 MiB 时经 `read_page` 读全文(解析器按
   完整输出设计,head+tail 截断视图会丢中间段);超限/读失败退
   `output_view`——与 WP-01 有界内存一脉,解析绝不为门槛。
3. **只解析终态**(`completed/timeout/killed`):background 的 running
   态结果不含产出,跳过——否则每次后台启动都白记一条 no_match
   fallback(测试锁死此语义)。
4. **命中即替代通用视图**(非增强追加):摘要是解析器按完整输出提炼
   的亮点(hosts/ports/注入确认/loot),严格优于 head+tail 机械截断;
   原文已落盘且 `output_path`/`sha256` 仍在结果里,模型可 read_output
   分页核对。视图加 `[解析摘要:<tool>]` 前缀如实标记来源。
5. **无 index 只换视图**:loop 独立使用(无索引)时解析仍增强 LLM
   视图,facts 静默不记——增强语义不因配置缺失变成异常。

## 踩坑

1. **POSIX `$t✓` 变量名粘连**:shell 里 `"$t✓"` 把多字节符号粘进变量
   名(`set -u` 下直接 fatal)——拼接后缀一律 `${t}…`(探针脚本修
   一处;与 HANDOVER 陷阱 13 的 zsh 坑同族:shell 文本处理处处是界)。
2. **本机代理会劫走 agent 的 curl**:`ALL_PROXY` 指向死代理时 curl
   全军覆没,而 LLM API 在本机恰可直连——跑 e2e 的环境要
   `unset ALL_PROXY` + `NO_PROXY` 补 loopback(setup 文档「代理坑」
   已留复现步骤)。
3. **「模型截断自己的输出」是解析层新失败形态**:`| tail -20` 把
   结构化内容截没,parse_fallback no_match 静默——设计内,但提示
   prompts 可引导模型「扫描类命令保持完整输出」(候选改进,不在
   本 WP 改 prompt 做实验)。
