## 交付物

- `src/foam/agent/tool_catalog.py`:静态目录(纯数据,零逻辑)——7 个渗透
  阶段分组(recon/vuln/web/password/sniff/post/report)共 **137** 个常用
  工具,每条 `ToolEntry(name, summary, usage, package)`。`name` 即

  exploitdb)。
- `src/foam/agent/toolmap.py`:盘点器 + 地图文本。
  - `scan_tools(which=, dpkg_packages=, extra_dirs=, catalog=)`——四个注入缝
    全是关键字参数,测试全伪环境,不碰真机;`parse_dpkg_l` 单独可测。
  - 探测链按序命中即停:`which` → 常见目录直查(含 `/opt/<工具>` 目录形态,
    覆盖 PATH 缺 /usr/sbin 等情形)→ `dpkg -l` 包名兜底;无 dpkg 的机器
    该项整体降级(`ScanResult.dpkg_available` 如实标记)。
  - `render_tool_map(scan, budget_bytes=2048, current_phase=None)` 保证
    ≤ 预算(UTF-8 字节);`render_startup_line(scan)` 一行启动日志。
  - 缺失工具只标注(附 apt 包名),**绝不自动安装**——装不装是 LLM 结合
    任务的决定,且 `apt install` 本身也是一条过 scope 护栏与审计的命令。

## 设计取舍

1. **name 即探测键,死链从结构上不可能**:目录条目没有「显示名/探测名」
   两个字段可漂移;`package` 只在命令名 ≠ apt 包名时填写,盘点兜底与
   「未安装可 apt install X」提示共用同一出处。
2. **探测链 which → 常见目录 → dpkg,命中即停**:目录直查覆盖 PATH 缺
   `/usr/sbin` 的最常见情形;`/opt/<工具>` 以目录形态计已装(无线工具与
   大 GUI 常装成目录);dpkg 兜底接住「命令名 ≠ 包名」与 PATH 之外安装。
   无 dpkg 的机器(macOS/容器)整体降级为 which+路径,`dpkg_available`
   如实标记进启动行。
3. **预算分级降级,可用名是最后防线**:层级 3(usage 全带)→ 2(去
   usage)→ 1(可用名压缩成一行 + 未安装清单)→ 0(只剩可用名,未安装
   由组标题计数兜底);`current_phase` 指定组始终高一级细节。实测字节数
   (137 全装/仅 2 装两种极端):

   | 层级 | 全装(无 phase) | 全装(phase=web) | 稀疏(2 装) |
   |---|---|---|---|
   | 3 | 8123 | 8123 | 2413 |
   | 2 | 5339 | 5686 | 2375 |
   | 1 | 1783 | 2220 | 2324 |
   | 0 | 1783 | 1783 | 438 |

   即:真实 Kali(近全装)默认预算落 1 级——全量工具名进 prompt;稀疏机
   落 0 级——可用名全保,未安装清单让位(指定 current_phase 时该组未安装
   清单仍保住)。硬截断兜底仅理论情形(预算 < 0 级体积)。
4. **未安装清单只保到 1 级**——这是开发中期的实测修正:初版 0 级也带
   missing 名单,实测稀疏机 133 个 missing 名 ≈ 1600B,把「可用工具名」
   这一核心价值挤出预算;调整为可用名优先(组标题 `9/33 可用` 的计数本身
   就是缺失标注,规格「缺失只标注」在每一级都成立)。
5. **`dpkg -l` 解析只认 `ii` 行**:`rc`(卸载残留配置)不算已安装——按
   它判可用会让 LLM 调到不存在的命令;`:amd64` 多架构后缀剥除后再比对。
6. **正文不含标题**:`# 工具地图` 标题由 WP-04 prompts 层加,本模块只产
   正文——注入契约单测经真实 `build_system_prompt` 走一遍,占位文本被
   整段替换有断言。

## 踩坑

1. **noqa 要挂在诊断锚定行**(陷阱 8 的新变体):`subprocess.run(...)` 的
   S603 锚在调用行、S607 锚在 `["dpkg", ...]` 参数行——合写
   `# noqa: S603 S607` 在调用行盖不住 S607,须拆成两行各挂。理由注释仍按
   陷阱 8 写在上方独立行。
2. **E501 与中文长参数行**:目录条目行超 88(全角字符按 1 计也容易在长
   usage 下超),解法照旧:多行调用 + 每参数一行。
3. **ruff format 不是本仓门槛**:全仓 15 个文件(含 12 个已入库文件)与
   format 规范有出入,故本 WP 只对齐 `ruff check`,不跑 format 避免制造
   与既有代码风格不一致的孤立「标准」文件。

## 留给 WP-10 的接线接口(cli.py 是 WP-10 拥有,本 WP 未动)

```python
from foam.agent.toolmap import render_startup_line, render_tool_map, scan_tools

scan = scan_tools()                       # 启动时一次,~137 次 which,毫秒级
```

跟踪阶段,接线先一律 `None`;后续若 loop 增加阶段跟踪,直接传入分组 key
(recon/vuln/web/password/sniff/post/report)即可,接口已就位。

  [recon 27/33, vuln 12/17, web 10/18, password 10/15, sniff 22/29,

  清单双双保住)。交叉验证:用补测报告的 41 个缺失清单在开发机重建
