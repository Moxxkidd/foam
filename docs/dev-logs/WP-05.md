## 设计取舍

1. **输出层整体复用 WP-01**:PTY 单流正好对应 `OutputRecorder(split=False)`
   的既有情形,分流路径/哈希为 None;落盘/哈希/ring 有界一行新代码都没写。
   sha256 定稿时机 = 读循环 EOF + 子进程收割之后(自然退出与被杀都覆盖)。
2. **控制终端(ctty)显式获取**:`start_new_session=True`(setsid)+
   `preexec_fn` 里 `ioctl(0, TIOCSCTTY)`。只 isatty 不够——ssh 读密码直接
   开 `/dev/tty`,没有 ctty 就拿不到密码提示。preexec_fn 在 fork/exec 间只
   调 syscall 级函数且进程无线程,风险可控;失败静默降级(多数工具仍可用)。
3. **提示识别 = 结构化事件,不是原文转述**:所有正则锚定清洗后文本的
   **尾部**(提示一定出现在输出末尾等待输入处),正文提到 password/msf6
   不误报(有专项 fixture);同一输出位置只触发一次(offset 去重,防
   msfconsole 重绘刷事件);事件随 session_read 排空。meterpreter 提示符
   顺手收录——WP-12 要用,但只保通道,语义管理是排除项。
4. **ANSI 清洗在字节层、只在视图**:CSI/OSC/DCS/字符集/两字节转义 regex
   按长序列优先匹配;退格成对消去;CR 做终端列叠加语义(进度条取最后一
   帧)。清洗发生在「组包后的文本段」上,不逐 chunk——转义序列跨 chunk
   切断只在读边界留装饰性瑕疵。
5. **session_read 增量游标 + 预算**:游标按原始字节;单次最多 `limit`
   原始字节(默认 16KB),`has_more` 提示续读;`wait_pattern` 给出即隐含
   等待(默认 30s,显式 0 = 立即返回当前增量),匹配窗口取尾部 64KB。
6. **closed 与 exited 严格区分**:`closing` 旗标——我们杀的记 closed,
   自然退出记 exited;close 对 exited 也有效(释放 fd 与配额)。
7. **上限按「未关闭」计**:已退出未 close 的会话仍占 master fd,计入
   `max_sessions`(默认 8),逼 LLM 养成 close 习惯;`aclose()` 供 WP-04
   kill switch / engagement 收尾一键清场。
8. **EIO 即 EOF**:Linux 上 PTY 对端关闭后读 master 报 EIO(macOS 报空
   读),读循环统一按 EOF 处理再收割,跨平台行为一致。

## 踩坑

1. **closed/exited 竞态**:读循环 finally 先把状态标 exited,close 再检查
   已晚——被杀的会话显示成「自然退出」。加 `closing` 旗标在杀之前置位,
   读循环按旗标定终态。(首轮 13 个失败里 5 个是它。)
2. **CR 覆盖语义的正确预期是列叠加**:`aaaa\rbb` 的终端真值是 `bbaa`
   (bb 覆写前两列,余列保留),不是 `bba`——初版测试预期写错,实现是
   对的;修正测试。
3. **事件等待的丢失唤醒**:`data_event.clear()` 必须先于读文件,否则
   「读完判定」与「clear 之间」到达的块会被清掉,read 傻等到超时。
4. macOS 开发机上 PTY EOF 表现为空读(Linux 是 EIO)——两者都要兼容,
   见设计 8;`preexec_fn` 配合 `start_new_session` 在 macOS 工作正常。
5. ruff E501 对中文按字符计长:schema 描述字段统一用小括号隐式拼接折行。
